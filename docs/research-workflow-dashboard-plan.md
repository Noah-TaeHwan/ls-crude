# 연구 워크플로우 대시보드 — 기획·디자인 계약

2026-09-08. 목적은 가설의 재미, 실제 관측값, 접근 결과, 다음 행동을 한 화면에서 따라가게 하는 것이다. 이번 버전은 GitHub 연구 기록을 읽는 공개 관측판이다.

## 화면과 데이터

- 홈: 최근 접수 후보와 현재 접근 상태를 짧게 보여주고 `/research#intake`로 연결한다.
- 연구 화면 상단: 가설 → 접근·샘플 → 개별 시각화 → 선택적 조합의 절차를 보여준다. 절차 안내를 완료율로 표현하지 않는다.
- 접수 장부: `research/candidates/ledger.csv`와 개별 카드가 정본이다. 실제 관측값, 수집 상태, 검정 여부, 판정 이유, 다음 행동·담당·재검토일, 원문을 검색·필터로 탐색한다.
- 기존 factors 장부는 아래에 보존한다. ALT와 legacy는 서로 겹치므로 건수를 합산하지 않는다.
- 카드 변경 이력과 연결된 조사 노트로 접근 시도·실패·검토 근거를 따라간다. AI 검토와 사람 검토를 구분한다.
- 누락·형식 오류는 오류 상태로 표시하고 0개로 꾸미지 않는다. E1·샘플 접근을 검정 완료나 채택 신호로 표시하지 않는다.

## 시각과 상호작용

기존 깊은 녹색·아이보리·앰버·민트 디자인을 유지한다. 과정은 얇은 단계 목록, 결과는 넓은 카드와 접히는 상세로 표현한다. 검색·판정 필터·더 보기·빈 결과 초기화는 키보드로 동작하고 상태를 문자로 표시한다. 모바일에서 카드가 한 열이 되고 가로 넘침이 없어야 한다.

## WTI 전 거래일 종가

기존 Yahoo CL=F 완료 일봉 수집기를 재사용한다. 뉴욕 오늘 날짜는 제외하고 마지막 이용 가능한 일봉을 표시한다. 달력상 어제가 아니라 최근 완료 거래일이며 Yahoo 일봉 종가를 거래소 공식 정산가로 부르지 않는다. 가격 기준일, 수집 확인시각, 자동 갱신 일정, 지연 상태를 함께 표시한다.

기존 GitHub Actions의 데이터 전용 PR 경로를 유지한다. 주말에도 하루 한 번 수집 확인하도록 일정 빈틈을 수정한다. 성공한 마지막 스냅샷을 보존하며 실패시 0·가짜 최신값으로 바꾸지 않는다. 현재 배포는 GitHub 통합이 자동 갱신을 실제 반영하는지 확인한다.

## 수락 기준

1. 최신 ALT 도로·파이프라인 카드가 실제 정본 필드와 같은 상태·이유로 보인다.
2. 전체 접수 검색·필터·0건 복구·원문/이력 탐색이 동작한다.
3. 불완전한 CSV·카드·상태는 조용히 누락되지 않는다.
4. WTI 현재 NY 날짜 일봉 제외 테스트, 실제 갱신 실행·CI·배포 readback을 구분해 확인한다.
5. 타입체크·빌드·테스트와 ego 브라우저 데스크톱/모바일 검증을 통과한다.

Agency-Agents: UI Designer 기획 검토, explorer 가격 경로 조사, Frontend Developer 구현, 독립 검토 역할. 메인 에이전트가 증거를 직접 재검증한다. 승인된 개발 요청을 이 범위로 구체화하며 연구 모델·복합 지수 개발은 포함하지 않는다.

## 운영 근거와 확인 범위

- 기존 자동 실행 `34124618730`은 schedule로 성공했고 데이터 PR #62를 병합했다. 기존 경로를 대체하지 않는다.
- 일정은 `30 6 * * *` UTC, 매일 15:30 KST다. [GitHub schedule 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)처럼 실제 실행은 지연될 수 있으므로 정각 반영을 보장하지 않는다.
- `notify` 작업의 `gh`가 checkout 없이 저장소를 찾도록 `GH_REPO`를 지정한다. 실패 알림을 고의 발생시키지는 않는다.
- NY 자정 전의 금요일 봉 제외, 토요일의 금요일 봉 포함, 휴일 공백을 채우지 않음을 실제 단위 검사로 확인한다.
- 초기 운영 페이지는 `febd4e7`에서 WTI 기준일 2026-09-04와 확인시각 2026-09-07 21:57 KST를 표시했다. 가격 자체와 갱신 시각은 별개다.
- PR #64는 `febd4e7`로 병합했고 그 시점 local main/origin main/GitHub main 일치를 확인했다. 해당 작업 브랜치만 정리했다.

## 구현·검수 결과

- 빌드에 CSV와 후보 Markdown을 포함하고 핵심 12필드를 대조한다. 새 카드가 추가되면 다음 배포부터 반영된다. DB·수동 복제 장부를 추가하지 않았다.
- 현재 접수 50개와 기존 팩터 91개를 각각 표시한다. 등록순 홈 2개, 전체 검색·판정 필터·6개씩 더 보기를 구현했다.
- 과거 선택 필드 누락은 ‘기록 없음’으로 표시하고 핵심 불일치는 접수 오류로 표시한다.
- UI Designer의 독립 검토 뒤 워크플로우 링크와 모바일 상세 1열 배치를 보완했다. Reality Checker의 변경 코드·테스트 검토는 차단 이슈 없음이다.
- 메인 직접 검증: 연구 테스트 36개, 앱 테스트 5개, 타입체크·빌드 통과. 앱 테스트에는 실제 원장 카드 대조 및 잘못된 CSV·중복·상태·경로·카드 불일치 거부가 포함된다.
- ego 브라우저: 320·390·1440px 홈/연구 화면의 가로 넘침 없음, 검색 1건·0건·초기화, 6→12개 더보기, 종료 필터 10건, Enter로 상세 열기, 홈 최신 2개와 갱신 일정 확인. 자동화의 비어 있는 검색어 입력 직후 상태 확인이 빨라 별도 초기화 버튼·대기 후 재검증했다.
- [데스크톱](design-evidence/research-workflow/desktop.png), [모바일 상세](design-evidence/research-workflow/mobile-detail.png), [브라우저 폭·오류 기록](design-evidence/research-workflow/browser.json).
- 실제 사람 사용자 실험·VoiceOver·WebKit은 미검증이다. 개발 브라우저·로컬 테스트를 운영 배포 확인으로 간주하지 않는다.
- graphify AST 갱신 완료. 기존 SQL parser 누락 경고는 별도이며 SQL 그래프 완전성은 주장하지 않는다.
