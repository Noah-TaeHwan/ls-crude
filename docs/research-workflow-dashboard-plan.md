# 연구 워크플로우 대시보드 — 기획·디자인 계약

2026-09-08. 목적은 가설의 재미, 실제 관측값, 접근 결과, 다음 행동을 한 화면에서 따라가게 하는 것이다. 이번 버전은 GitHub 연구 기록을 읽는 공개 관측판이다.

## 화면과 데이터

- 홈: 최근 접수 후보와 현재 접근 상태를 짧게 보여주고 `/research#intake`로 연결한다.
- 연구 화면 상단: 가설 → 접근·샘플 → 개별 시각화 → 선택적 조합의 절차를 보여준다. 절차 안내를 완료율로 표현하지 않는다.
- 접수 장부: `research/candidates/ledger.csv`와 개별 카드가 정본이다. 실제 관측값, 수집 상태, 검정 여부, 판정 이유, 다음 행동·담당·재검토일, 원문을 검색·필터로 탐색한다.
- 기존 factors 장부는 아래에 보존한다. ALT와 legacy는 서로 겹치므로 건수를 합산하지 않는다.
- 카드 변경 이력과 연결된 조사 노트로 접근 시도·실패·검토 근거를 따라간다. AI 검토와 사람 검토를 구분한다.
- 누락·형식 오류는 오류 상태로 표시하고 0개로 꾸미지 않는다. E1·샘플 접근을 검정 완료나 채택 신호로 표시하지 않는다.

## 시각과 상호작용

기존 깊은 녹색·아이보리·앰버·민트 디자인을 유지한다. 과정은 얇은 단계 목록, 결과는 넓은 카드와 접히는 상세로 표현한다. 검색·판정 필터·더 보기·빈 결과 초기화는 키보드로 동작하고 상태를 문자로 표시한다. 모바일에서 카드가 한 열이 되고 가로 넘침이 없어야 한다.

## WTI 전 거래일 종가

기존 Yahoo CL=F 완료 일봉 수집기를 재사용한다. 뉴욕 오늘 날짜는 제외하고 마지막 이용 가능한 일봉을 표시한다. 달력상 어제가 아니라 최근 완료 거래일이며 Yahoo 일봉 종가를 거래소 공식 정산가로 부르지 않는다. 가격 기준일, 수집 확인시각, 자동 갱신 일정, 지연 상태를 함께 표시한다.

기존 GitHub Actions의 데이터 전용 PR 경로를 유지한다. 주말에도 하루 한 번 수집 확인하도록 일정 빈틈을 수정한다. 성공한 마지막 스냅샷을 보존하며 실패시 0·가짜 최신값으로 바꾸지 않는다. 현재 배포는 GitHub 통합이 자동 갱신을 실제 반영하는지 확인한다.

## 수락 기준

1. 최신 ALT 도로·파이프라인 카드가 실제 정본 필드와 같은 상태·이유로 보인다.
2. 전체 접수 검색·필터·0건 복구·원문/이력 탐색이 동작한다.
3. 불완전한 CSV·카드·상태는 조용히 누락되지 않는다.
4. WTI 현재 NY 날짜 일봉 제외 테스트, 실제 갱신 실행·CI·배포 readback을 구분해 확인한다.
5. 타입체크·빌드·테스트와 ego 브라우저 데스크톱/모바일 검증을 통과한다.

Agency-Agents: UI Designer 기획 검토, explorer 가격 경로 조사, Frontend Developer 구현, 독립 검토 역할. 메인 에이전트가 증거를 직접 재검증한다. 승인된 개발 요청을 이 범위로 구체화하며 연구 모델·복합 지수 개발은 포함하지 않는다.

## 운영 근거와 확인 범위

- 기존 자동 실행 `34124618730`은 schedule로 성공했고 데이터 PR #62를 병합했다. 기존 경로를 대체하지 않는다.
- 일정은 `30 6 * * *` UTC, 매일 15:30 KST다. [GitHub schedule 문서](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#schedule)처럼 실제 실행은 지연될 수 있으므로 정각 반영을 보장하지 않는다.
- `notify` 작업의 `gh`가 checkout 없이 저장소를 찾도록 `GH_REPO`를 지정한다. 실패 알림을 고의 발생시키지는 않는다.
- NY 자정 전의 금요일 봉 제외, 토요일의 금요일 봉 포함, 휴일 공백을 채우지 않음을 실제 단위 검사로 확인한다.
- 초기 운영 페이지는 `febd4e7`에서 WTI 기준일 2026-09-04와 확인시각 2026-09-07 21:57 KST를 표시했다. 가격 자체와 갱신 시각은 별개다.
- PR #64는 `febd4e7`로 병합했고 그 시점 local main/origin main/GitHub main 일치를 확인했다. 해당 작업 브랜치만 정리했다.

- UI Designer의 독립 검토 뒤 워크플로우 링크와 모바일 상세 1열 배치를 보완했다. Reality Checker의 변경 코드·테스트 검토는 차단 이슈 없음이다.

## 운영 반영 확인

PR #65 병합·main CI 성공 뒤 수동 갱신 run `34180585677`의 validate/publish가 성공했다. 데이터 PR #66이 `3208487`로 자동 병합되고 Vercel 배포도 성공했다. ego 운영 화면과 `/wti-market-snapshot.json`에서 기준일 2026-09-04, 종가 91.48 USD, checkedAt 2026-09-08T02:36:37Z 일치를 확인했다. 운영 연구 화면의 후보 검색에서 도로 카드 원문 GitHub 링크로 실제 이동했다. 매일 cron 설정은 확인했고 새 주말 예약 실행 자체는 아직 도래하지 않았다.

가격 기준일이 4일 지난 상태에서도 수집 확인은 성공할 수 있다. 그래서 공통 stale 배지는 “최신성 확인”으로 표시하고, 마지막 확인 지연과 가격 기준일 경과의 구체적인 이유를 본문에서 구분한다. 휴장일 달력 판정을 구현했다고 주장하지 않는다.

## 최신 시세 표시 수정

사용자가 최신 가격 부재를 지적하여 확인한 결과, Yahoo의 최신 수신값은 존재했지만 NY 오늘 일봉 제외 규칙 때문에 화면에서 보이지 않았다. 완료봉 계산에 이 값을 밀어 넣지 않고 별도의 서버 조회를 추가했다.

- 홈 요청에서 Yahoo chart `regularMarketPrice`와 `regularMarketTime`을 읽는다. 제공자 시세시각과 우리 조회시각을 구분한다. 제공자 지연이 있어 실시간 체결가로 부르지 않는다.
- 인스턴스별 정상 조회 60초 캐시·3.5초 timeout, 실패 시 마지막 정상값의 원래 시각을 보존하고 실패를 표시한다. 인스턴스 재시작 뒤 실패하면 미확보다.
- 보이는 홈은 5분마다 loader를 재검증한다. 완료 일봉과 변동성은 기존 일일 자동화로 별도 유지한다. Yahoo `chartPreviousClose`는 차트 첫 기준값일 수 있어 전 거래일 대비로 사용하지 않는다.
- Agency API Tester가 실제 Yahoo 응답의 약 10분 지연과 `currentTradingPeriod`의 시점 불일치를 확인했다. 세션 마감이나 공식 정산으로 추정하지 않는다.

## 분봉 그래프와 최신 시세의 연결

- Agency Data Engineer가 실제 Yahoo `5m/1d`, `5m/5d`, `1m`, `2m`, `15m`, `60m` 응답을 확인했다. 현재 `1d` 분봉은 비어 있고 `5d`의 유효 분봉은 2026-09-04까지만 있다. 9월 8일 최신 metadata 시세와 다른 가용 범위다. 직접 기간 지정도 이후 분봉을 복원하지 못했다.
- 원 제공자의 실제 5분봉 선과 최신 metadata 시세의 다이아몬드 점을 하나의 실제 시간축에서 구분한다. 최신 시세를 가짜 완료봉으로 붙이지 않는다. 관측이 없는 주말·휴일·누락 구간을 선으로 잇지 않는다.
- 분봉 마지막 시각·가격과 최신 시세 시각·가격·조회시각을 각각 표시하고, 15분 이상 차이가 나면 공급자 분봉 지연을 표시한다.
- 0개 분봉이면 실제 최신 시세 한 점만 표시한다. 1개·평평한 가격·음수 가격을 처리한다. null은0으로 바꾸지 않고, 중복·역순·미래 시각·잘못된 배열은 해당 분봉만 거부한다.
- 분봉 부분 실패 시 마지막 정상 분봉을 기존 시각 그대로 유지한다. 전체 조회 실패는 기존 시세·분봉을 보존하고 실패를 표시한다. 현재 메모리 캐시는 영구 역사 저장소가 아니다.
- 시세·그래프 다시 확인은 페이지 전체 새로고침 대신 loader 재검증으로 수행한다. 날짜 탐색 선택은 관측 종류·시각으로 유지하고, 새 자료로 사라진 선택은 최신 시세로 돌아간다.
- UI Designer 기준: 시간 비례 x축, 가격이 평평해도 중앙 표시, 결측 구간 단절, 키보드 시각 탐색, 모바일 넘침 없음, 완료 일봉/RV 상태와 분봉 상태 분리.

분봉 검증: 메인 ego 브라우저에서 실제 Yahoo 응답과 SVG 1,032개 좌표·4개 단절 구간·최신 시세 표식이 일치함을 확인했다. 시각 탐색 Home/End, 새로 확인 후 기존 시각 선택·문서 유지, 320/390/1440px 가로 넘침 없음·브라우저 오류 없음. UI Designer 지적으로 공급자 지연 경고를 그래프 위에 배치하고 모바일 최저·최고값을 HTML 본문에도 표시했다. Reality Checker 독립 코드·대상 테스트 검토 차단 이슈 없음. 타입체크·빌드·앱 8개·연구 36개 테스트 통과. 분봉 공급 지연 자체는 해결됐다고 주장하지 않는다.

## 현재 가격 UI — 단일 일봉으로 통합 (이전 분봉 설계 대체)

사용자의 정정에 따라 분봉 선·별도 최신 시세 점·완료 일봉 그래프를 폐기하고 **WTI 일봉 그래프 하나**로 통합한다. 위 분봉 관련 절은 당시 시행착오 기록이며 현재 설계가 아니다.

- Yahoo `interval=1d&range=5y`의 실제 OHLC를 받아 최신 일봉까지 표시한다. 메타 시세를 별도 점이나 가짜 일봉으로 추가하지 않는다.
- 5년·3년·1년·6개월·3개월·1개월·1주일 버튼. 기본 1년. 모든 기간의 단위는 일봉이고 끝점·상단 가격은 같은 최신 일봉이다. 월말·윤년은 달력 기준으로 제한한다.
- 캔들·거래일 탐색·선택 일봉 OHLC 표시. 진행 중일 수 있는 마지막 일봉은 변경 가능으로 표시한다. 날짜는 Yahoo 타임스탬프의 뉴욕 날짜이며 조회·원천 시각은 KST를 함께 표시한다.
- 실제 응답은 유효 OHLC 1,258개와 누락 3개였다. 누락은 채우지 않는다. 전체 조회가 실패하면 마지막 정상 일봉 전체를 원래 시각 그대로 보존한다.
- 완료 일봉 기반 RV는 가격 그래프가 아닌 접힌 설명 영역에만 남긴다. 별도 기준일을 명시하며 진행 중 일봉을 RV 계산에 혼합하지 않는다.
- 기존 분봉 컴포넌트·시세 전용 서버 모듈과 해당 테스트를 제거하고 단일 일봉 수집·기간·OHLC 테스트로 교체한다.
