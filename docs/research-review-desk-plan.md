# 리서치 페이지 기획 — 검토와 다음 행동

## 목적

메인은 확보한 자료를 관측하는 화면이다. 리서치는 가설의 근거·한계·판정을 확인하고 다음 조사 행동을 결정하는 화면이다. 발표 때도 성공한 그림뿐 아니라 보류·실패·정정의 이유를 설명할 수 있어야 한다.

방문자가 답할 질문은 네 가지다: 무엇을 측정하려 했나, 실제로 무엇을 확보했나, 왜 유지/보류/종료했나, 다음에 누가 무엇을 확인하나.

## 화면 구성

1. 짧은 목적 안내와 메인 자료 탐색 링크. 메인의 큰 소개·WTI·그래프·실시간 조회를 반복하지 않는다.
2. ALT 가설 장부를 중심으로 이름/가설/담당 검색, 판정과 실제 작업 상태 필터. 카드에는 관측 대상·확보 상태·판정 이유·다음 행동을 표시하고 상세 근거는 펼쳐 본다.
3. 과거 factors 검정 장부는 별도 접힌 참고 영역. 기존 후보 링크와 검색은 유지한다. ALT와 같은 모집단이 아니므로 건수를 합산하지 않는다.
4. 판정 방법과 기록 출처는 접어서 제공한다. 팀 소개는 메인/공통 푸터와 중복하므로 반복하지 않는다.

## 데이터와 구현 경계

- 현재 정본에서만 계산한다. 원본 확보와 검정 실행, KEEP과 효과 인증을 구분한다.
- 상태별 수는 겹칠 수 있으며 완료율이나 서로 배타적인 단계가 아니다.
- 담당은 원장 기록이며 사람의 수락이 확인되지 않으면 배정 제안으로 표시한다.
- 새 우선순위 점수·자동 추천·DB·편집 기능은 추가하지 않는다.
- 기존 카드/파서/스타일을 재사용한다. 연구 페이지에서 외부 관측 API 호출과5분 polling을 제거한다.
- 옛 /research?sample=… 주소는 메인의 같은 자료로 연결한다. ?candidate=018 같은 과거 검정 링크는 유지한다.

## 검수 기준

리서치에 WTI/관측 그래프 중복 없음; 검색·판정·작업상태 필터/초기화 동작; 오류를0건으로 표시하지 않음; 모바일 가로 넘침 없음; 장부별 건수 구분; 메인 그래프 링크/옛주소/과거후보 딥링크 유효; 타입검사·빌드·테스트·Ego 검수.

## 구현·검토 결과

- Reality Checker 독립 정적 검토 후 판정 기준 링크의 펼침 동작, 오래된 WTI 문구, 정본 기반 통과 수 검사를 보완했다.
- 리서치의 외부 관측 조회·polling·그래프를 제거했다. 6종 sample 옛주소는 메인으로308 연결하며 candidate=018은 과거 장부를 열고 검색을 유지한다.
- ALT 검색/작업 상태/후속 판정은 AND 결합. 원본 확보38개, 특정 LA 후보1개, 차단과 조합 시0개를 실제 브라우저로 확인했다(검수 시점 정본 기준).
- 320/390/1440px 가로 넘침 없음, 기본 과거 장부/방법 접힘, 판정 기준 링크 클릭 시 펼침. [Ego 증거](design-evidence/research-review-desk/).
- typecheck/build 및 Node26 tests PASS. SSR 테스트 중 외부 Yahoo 조회 실패가2회 발생해 눈금 검사가 막혔다. 운영 코드는 바꾸지 않고 테스트 자식 프로세스에만 명시적 Yahoo fixture를 주입했다. 기존 가격 눈금 검증은 유지하고 fixture 가격도 대조한다. fixture는 운영 앱에서 로드되지 않는다.
- 실제 iOS/VoiceOver 검수는 미실행. 새로운 연구·가격 데이터나 검정 결과를 만들지 않았다.
