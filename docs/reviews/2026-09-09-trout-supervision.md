## 직접 발견한 문제

1. PR #91은 research CI 성공이지만 app CI 실패 상태에서 병합됐다. run34298545259의 정본 파싱/SSR 테스트2건 실패. 과거부터 있던 실패도 현재 완료를 보증하지 않는다.
2. 실제 urllib `HTTPError(403)`를 모의 주입하면 다음 대상까지 요청하고 status complete가 된다. 반환값403만 모의한 기존 자가검사는 실제 오류 경로를 검증하지 못했다.
3. 중단된 요청 자체의 URL/시각이 영수증에 없을 수 있다. 전부 실패했는데 complete로 표시하는 경우도 구분해야 한다.
4. `parse_number('(12.00')`와 `parse_number('12.00)')`가 정상12로 수락된다. 짝 없는 괄호를 거부해야 한다.
5. 재생 경로는 입력 manifest SHA 검사 없이 원본을 읽고 기존 출력 파일을 덮어쓴다. 변조·누락을 거부하고 기존 빈티지 변경을 막아야 한다.
6. 비중은 빈+적재수출을 분모로 계산하지만 화면 상단과 표는 제공기관 totalExports를 분모처럼 표시한다. 2022-11은 계산327,788 vs 제공327,888 TEU로100 차이. 2020-07/2025-03/2025-10도 차이가 있다.
7. 자동 갱신 없는 고정 자료를 관측 영역에 새 카드로 추가했다. 사용자 정정에 따라 네 번째 사례로 이동하며 기존 상세 URL은 새 사례로 연결한다.

## 보존·대사 (repo empirical only)

감독자 직접 확인: 원본13개·1,671,875bytes가 request.json의 파일별 SHA/용량과 일치. CSV138행의 빈/(빈+적재) 비중을 Decimal로 전수 재계산해 일치. 기존 출력 해시는 별도 비교 기준으로 보존했다. 제공기관 합계의 차이는 보정하지 않는다.

## 사용자 추가 정정 — 시정·탱커도 같은 탐색 UI

별도 FIELD NOTES 영역을 제거하고 여섯 버튼(수박·제주·도일·LA항·갤버스턴 시정·싱가포르 탱커)으로 묶는다. 두 갱신 관측은 기존 서버 캐시·원단위·시각·갱신 버튼을 유지한다. 연구 페이지에서도 loader로 자료를 읽고 열린 화면의5분 확인을 유지한다. 사례 선택만으로 재요청하지 않으며 수동/주기 갱신은 정상 동작한다. `#observations` 기존 홈 앵커는 통합 자료 탐색으로 연결한다.

시정·탱커 상세 화면의 돌아가기 링크도 해당 버튼이 선택된 자료 탐색으로 연결한다.
