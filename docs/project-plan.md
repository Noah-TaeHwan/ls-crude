# LS CRUDE — 대안 데이터 탐색·발표 계획

이스트캠프 AI 퀀트 4기 미니 프로젝트 · 오태환(Noah) × 손성찬. 계획 기준일은 **2026-09-07 KST**, 발표 마감은 **2026-09-15 09:00 KST**다. 합격 기준은 근거를 따라갈 수 있는 일관된 연구 이야기를 발표하는 것이다.

이번 작업은 **연구 OS 설치**다. 문서·빈 신규 장부·템플릿·검증 기록을 마련하며, 아래 이후 일정은 실행 계획이다. 문서 작성으로 후보 탐색·수집·검정·팀원 합의가 완료됐다고 보지 않는다.

## 목표와 범위

작고 특이하지만 설명 가능한 현실 활동의 흔적이 원유 공급·수요·지정학과 어떻게 연결될 수 있는지 찾는다. Pentagon Pizza Index에서는 **관측 가능한 활동 → 민감한 맥락 → 검정할 시장 관계**라는 질문 구조를 가져온다. 특정 주문 자료나 같은 제품을 복제할 필요는 없다.

| 포함 | 이번 범위 밖 |
| --- | --- |
| 후보·출처·접근 방법·실패·보류를 추적하는 연구 OS | 새 대시보드 기능·디자인·배포 |
| 합법적으로 확보한 활동 시계열의 품질·공개시각 점검 | 접근 제한 우회, 금지된 스크래핑, 개인·기밀 정보 수집 |
| 자료가 있으면 단위·빈도·지역·집계가 명확한 지수 구축 | 자료 없는 합성 시계열·가짜 성과·인과관계 단정 |
| Yahoo `CL=F`와의 상관·lag·사건·placebo 검정 및 한계 | ML 고도화·수익성 개선·실거래를 발표 필수조건으로 삼기 |
| 실제 기각·차단·미검정 상태와 다음 조건을 보여주는 발표 | Apps-in-Toss·Substack·Comento·Toss live trading 서사 |

기존 계획의 롱숏 전략·모델 비교·백테스트는 이번 발표의 필수 산출물로 삼지 않는다. 지수나 유의한 관계가 없어도 연구 질문, 실제 조사 기록, 판정 이유와 남은 조건이 연결되면 발표할 수 있다.

**작업량 제안:** 동시에 깊게 조사하는 후보는 최대 3개, 발표 전 새 지수 구축은 최대 1개로 제한한다. 후보 수를 채우기 위해 행을 만들지 않는다. 현재 [팩터 인벤토리](../research/factors/README.md)를 먼저 살펴 중복을 피하며, [신규 장부](../research/candidates/ledger.csv)가 비어 있어도 기존 연구가 없다는 뜻은 아니다.

## 팀 운영과 소유권

기존 [연구 설계의 역할](research-design.md#역할)은 Noah의 데이터·피처 작업과 성찬의 모델·검정을 구분한다. 아래는 그 역할을 이번 목표에 맞춰 배정한 **제안**이며, 두 사람의 가용 시간·수락을 확인한 사실은 아니다. 09-07 인계에서 수락 여부와 가능한 작업 시간을 이 문서에 기록한다. 미수락 작업은 완료 약속으로 표시하지 않는다.

| 책임 | 주담당 제안 | 검토자 제안 | 인계 기준 |
| --- | --- | --- | --- |
| 범위·장부·문서·기한 관리 | Noah | 성찬 | 할 일·담당·마감·다음 행동을 같은 카드에서 확인 |
| 출처·약관·접근·수집·원본 보존 | Noah | 성찬 | 원본 경로·수집시각·체크섬·공개시각 또는 차단 근거 |
| 시계열 구축·품질·공개시각 정렬 | Noah | 성찬 | 단위·빈도·집계·결측 처리·as-of 정렬 확인 |
| 검정 사전 기록·누출 점검·반증·판정 초안 | 성찬 | Noah | 고정한 목표·분할·lag·placebo·재현 명령·결과 |
| 발표 자료·로컬 시연·장비 준비 | Noah | 성찬 | 근거 링크·오프라인 자료·시간 측정 리허설 |

매일 마감 때 작성자가 입력 경로·한 일·미실행 항목·판정·다음 행동을 기록하고, 다른 사람이 실제 파일이나 명령 출력을 읽어 검토 날짜와 결과를 남긴다. “읽음”만으로 재현 성공이라 쓰지 않는다. 결과가 다르면 유리한 수치를 택하지 않고 차이와 재현 실패를 기록한다.

하루 작업은 30–60분 단위로 나눈다. 출처 확인, 원본 등록, 시점 점검, 검정 계획, 재현 검토처럼 하나의 산출물을 끝낸다. 가용 시간이 부족하면 새 후보를 줄이고 실제 사례 한 개의 근거 연결을 먼저 마친다. 가설·구축·검정을 바꾸면 이유와 변경 시각을 기록하고, 동결 뒤 변경된 결과는 이전 검정과 구분한다.

## 지수가 없을 때도 발표할 이야기

발표 시간은 아직 확인되지 않았다. 우선 5분짜리 핵심 설명을 제안하고 09-07 인계에서 실제 배정 시간을 확인해 조정한다.

1. **질문:** 어떤 활동이 어떤 원유 맥락과 연결될 수 있는가. 피자 인덱스는 질문 구조의 참고다.
2. **탐색:** 실제 후보·원 출처·허용된 접근·수집 가능성과 실패를 보여준다.
3. **한 사례:** 확보된 자료가 있으면 구축·검정·한계, 없으면 차단 원인·미실행 항목·필요 자료를 따라간다.
4. **판정:** KEEP/KILL/PARK와 이유, 무엇을 알게 됐고 무엇이 아직 미검증인지 구분한다.
5. **다음 조건:** 재개에 필요한 자료·공개시각·표본·담당·날짜를 말한다.

신규 장부가 비어 있으면 README의 기존 사례인 [064 심야 식당 지수 기각](../research/factors/064-oilman-steakhouse-index/README.md), [070 휴게소 라면 지수 보류](../research/factors/070-highway-ramyeon-index/README.md)를 따라간다. 이번 setup에서는 문서의 판정과 감사 연결을 확인했으며, 외부 접근 상태·연구 결과를 새로 재검증한 것은 아니다. 070의 국내 경유 맥락도 WTI 검정 통과로 바꾸지 않는다. 최종 발표에 고를 때 당시 결과의 경로와 한계를 확인하며 이번 pass의 새 성과로 세지 않는다. 원본이 로컬에서 재현되지 않으면 남아 있는 기록과 재현 한계를 함께 설명한다.

빈 신규 장부·템플릿 자체는 설치 산출물이다. 실제 탐색 실패나 검정 성과를 대신하지 않는다. 발표에는 재확인된 기존 기록 또는 이후 실제 작업의 근거를 사용한다.
