# LS CRUDE — 쿠싱 관측판과 두 사람의 연구 워크플로우

작성일: 2026-09-08 · 대화 정리: Codex · 상태: 제품 방향과 작업 방식 제안

이 문서는 [앞선 연구 방향 메모](research-direction-2026-09-08.md)에 이어, 쿠싱을 중심으로 관측 데이터를 보여주는 제품과 Noah·성찬의 협업 방식을 정리한다. 역할 수락, 후보 선정, 신규 화면 구현이나 실험 착수를 확정한 문서는 아니다.

## 1. Noah의 제안

대화에서 제안한 흐름은 다음과 같다.

1. WTI의 중요한 허브인 쿠싱에서 어떤 움직임이 생기는지 관측한다.
2. 피자 주문량을 보고 사용자가 상황을 해석하듯, 우리는 관측 데이터를 인디케이터로 보여준다.
3. 모텔 불빛 등 다양한 데이터를 후보로 준비한다.
4. Noah와 성찬이 각각 여러 데이터를 조합하고, 설명력이나 상관관계를 검토한다.
5. 의미 있는 조합을 골라 펜타곤 피자 인덱스처럼 이해하기 쉬운 결과물로 만든다.

**검토 의견:** 관측 데이터를 보여주고 해석을 돕는 제품 방향은 적절하다. 다만 수백 개 데이터를 먼저 수집하고 좋은 상관관계가 나올 때까지 조합하는 방식은 줄이는 것이 좋다. 먼저 알고 싶은 현상을 정하고, 그 현상을 실제로 측정하는 소수의 관측을 확보한다.

## 2. 제품의 중심: 쿠싱 관측판

> **쿠싱의 원유 저장·운송 활동과 주변 상황에서, 평소와 다른 변화를 보여주는 관측 데스크.**

쿠싱은 WTI 선물의 실물 인도 지점이며 저장시설과 파이프라인이 연결된 내륙 허브다. 앞서 제안한 ‘유조선 안개 신호등’은 휴스턴·갤버스턴 항만을 염두에 둔 아이디어이므로 쿠싱 현지 활동으로 묶지 않는다. 나중에 연결 물류망의 외부 상황을 보여줄 수는 있지만, 공간적 범위와 연결 근거를 별도로 설명해야 한다. [CME 설명](https://www.cmegroup.com/education/courses/introduction-to-crude-oil/crude-oil-fundamentals/delivery-of-wti-futures)

앞선 메모에서 쿠싱은 발상 사례였다. 이번 대화는 **쿠싱을 실제 제품 범위의 중심으로 좁히자는 제안**이다. 이에 따라 기존 안개 신호등 추천을 쿠싱 프로젝트의 확정 과제로 자동 승계하지 않는다.

첫 화면에서 답할 질문은 다음 정도가 적절하다.

- 무엇이 평소보다 달라졌는가?
- 어느 지역에서, 언제 관측한 변화인가?
- 자료는 얼마나 최신이며 누락된 것은 무엇인가?
- 이 관측으로 알 수 있는 것과 아직 알 수 없는 것은 무엇인가?

‘쿠싱이 바쁘다’는 표현도 구체화해야 한다. 원유가 들어오는 활동, 나가는 활동, 운영 제약, 주변 생활 활동은 서로 다른 현상이다. 모두 증가한다고 같은 의미가 되지 않으므로, 처음에는 한 점수로 합치기보다 나란히 보여준다.

## 3. 해석은 사람이 하되 측정의 의미는 우리가 책임진다

아래는 표현 방식의 예시이며 실제 관측 결과가 아니다.

| 구분 | 모텔 불빛을 예로 든 표현 |
| --- | --- |
| 직접 관측 | 해당 구역의 야간 밝기가 기준 기간보다 높음 |
| 가능한 해석 | 활동 증가 가능성이 있지만 조명 변경·날씨 등 다른 설명도 있음 |
| 확인하지 못한 것 | 투숙객 수, 석유업계 종사자 유입, 비상근무 여부 |

밝기만 측정했다면 ‘밝기 변화’라고 명명한다. 투숙률·근무량·생산량으로 바꾸어 부르지 않는다. 모텔 불빛의 필요한 해상도·공개 지연·역사 자료 접근성은 이번 대화에서 확인하지 않았다.

사용자에게 해석을 맡기는 경우에도 다음은 표시한다.

- 원래 측정 단위와 평소 대비 변화의 계산 기준.
- 관측시각, 공개·수집시각, 자료의 유효기간.
- 실제 관측과 추정·가설의 구분.
- 결측·오래된 자료·측정 한계. 미수집을 활동 0으로 처리하지 않음.

## 4. 관측판·인덱스·회귀모형은 다른 산출물

| 산출물 | 먼저 정할 질문 | 회귀분석 필요 여부 |
| --- | --- | --- |
| 관측 대시보드 | 각각 무엇이 평소와 달라졌는가? | 없어도 됨 |
| 활동 인덱스 | 같은 활동을 나타내는 관측들을 어떻게 요약할 것인가? | 필수 아님 |
| 상태 추정모형 | 관측들로 실제 재고·운송량 등을 얼마나 잘 추정하는가? | 사용할 수 있음 |
| WTI 예측모형 | 관측들이 이후 가격·변동성에 추가 정보를 주는가? | 별도 연구로 사용할 수 있음 |

다중선형회귀의 구조는 다음과 같다. 아래는 개념 설명이며 실행한 모형이 아니다.

```text
Y = 기준값 + a × 관측1 + b × 관측2 + c × 관측3 + 오차
```

먼저 `Y`를 정해야 한다. 쿠싱 주간 재고 변화, 측정된 운송량, 다음 기간의 WTI 변동성은 서로 다른 목표다. ‘무슨 일이 일어나는 것 같다’는 아직 객관적인 정답 데이터가 아니다. 사건 발생 여부처럼 이진 목표라면 선형회귀를 자동 적용하지 않고 목표에 맞는 방법을 선택한다.

비교할 실제 상태 자료가 없더라도 관측판은 만들 수 있다. 다만 그 경우 상태 추정의 정확도나 예측력을 검증했다고 주장하지 않는다. 단일 지표를 보기 좋게 만든 것과 실제 현상을 잘 측정하는 것도 구분한다.

## 5. 설명력·상관관계·예측력의 차이

| 표현 | 의미 | 주의할 점 |
| --- | --- | --- |
| 상관관계 | 두 값이 함께 움직이는 정도 | 공통 계절성·추세·역방향 영향일 수 있으며 인과나 선행성을 보장하지 않음 |
| 표본 내 설명력 | 이미 본 자료에서 모형이 목표값의 변동을 얼마나 설명하는가 | 높은 값만으로 새 기간의 유용성을 판단하지 않음 |
| 새 기간의 예측력 | 선택·학습에 사용하지 않은 자료에서 얼마나 잘 작동하는가 | 같은 평가기간을 보고 반복 수정하면 더 이상 독립 평가가 아님 |
| 관측 도구의 유용성 | 최신성·해석 가능성·측정 신뢰성이 충분한가 | 가격 예측력이 없어도 별도로 평가할 수 있음 |

기존 관측과 거의 같은 정보를 반복 추가하는 것은 새로운 근거를 얻는 것과 다르다. 조합에는 ‘단일 관측보다 무엇을 더 알게 되는가’라는 이유가 있어야 한다.

## 6. 수백 개 조합을 먼저 돌리지 않는 이유

같은 과거 자료에 변수·시차·가중치를 계속 바꾸면 우연히 좋아 보이는 조합을 선택할 수 있다. 금융 연구에서는 반복 탐색에 따른 과적합과 시도 횟수의 문제가 지적돼 있다. [Bailey 외, The Probability of Backtest Overfitting](https://www.davidhbailey.com/dhbpapers/backtest-prob.pdf)

변수 선택과 표준화도 학습 자료 안에서 수행해야 한다. 전체 자료를 먼저 보고 고른 변수로 나중에 학습·평가를 나누면 평가 정보가 이미 선택에 들어갈 수 있다. [scikit-learn 데이터 누수 설명](https://scikit-learn.org/stable/common_pitfalls.html)

실무 제안은 다음과 같다.

- 아이디어 목록은 넓게 유지하되 실제 수집·분석 대상은 좁힌다.
- 단일 관측부터 확인하고, 같은 현상을 나타내는 소수의 자료만 조합한다.
- 목표·기간·평가기준을 두 사람이 공유한다.
- 실패한 조합, 바꾼 시차·가중치·변환도 한 장부에 기록한다.
- 조합이 필요하다면 단순한 단일 관측 또는 고정 기준보다 나아지는지 비교한다.
- 가장 높은 과거 점수를 찾는 것을 종료 조건으로 삼지 않는다.

기존 [프로젝트 계획](project-plan.md)의 **깊은 조사 최대 3개, 새 지수 구축 최대 1개** 제안을 유지하는 것이 적절하다. 이는 통계적으로 충분하다는 보장이 아니라, 두 사람이 자료와 근거를 끝까지 확인하기 위한 작업량 제한이다.

## 7. 두 사람의 실제 작업 순서

| 순서 | 작업 | 산출물과 진행 조건 |
| --- | --- | --- |
| 1 | 쿠싱에서 궁금한 현상을 최대 3개로 좁힌다 | 무엇을 알고 싶은지 한 문장씩 작성 |
| 2 | 현상이 남기는 흔적과 다른 설명을 적는다 | 관측 → 해석 가설 → 반증 조건 |
| 3 | 실제 데이터 샘플을 확보한다 | 원본·단위·지역·시각·지연·이용 조건. 확보 실패도 기록 |
| 4 | 관측을 하나씩 시각화한다 | 원 단위 추이·평소 대비 변화·결측·최신성 |
| 5 | 조합 필요성을 판단한다 | 단일 관측으로 부족한 점과 추가 자료의 역할. 불필요하면 조합하지 않음 |
| 6 | 정답 자료가 있으면 관계를 검정한다 | 목표에 맞는 오차·오탐·미탐 등을 단순 기준과 비교 |
| 7 | 서로 재현하고 발표 사례를 고른다 | 무엇을 알 수 있고 없는지 설명 가능한 관측판 또는 연구 기록 |

자료가 부족하면 4단계의 정직한 관측 시연이나 접근 실패 기록도 산출물이다. 억지로 회귀분석까지 진행하지 않는다. 사용할 수 있는 자료가 없는 관측을 실제 제품 기능처럼 채우지 않는다.

## 8. Noah와 성찬의 역할 제안

기존 프로젝트 계획의 데이터·피처 / 모델·검정 분담을 바탕으로 한 제안이다. 실제 가용 시간과 역할 수락을 확인했다는 뜻은 아니다.

| 책임 | Noah | 성찬 |
| --- | --- | --- |
| 질문 선정 | 만들고 싶은 관측 경험과 현상 제안 | 측정·검증 가능한 질문인지 검토 |
| 데이터 | 출처·접근·수집·시계열 구성 주도 | 단위·지역·시간 정렬·품질 확인 |
| 분석 | 단일 관측 시각화와 해석 가설 작성 | 기준모형·반증·필요한 검정 주도 |
| 재현 | 성찬의 분석을 실제 재실행 | Noah의 수집·변환을 실제 확인·재실행 |
| 발표 | 사용자가 읽을 화면·설명 흐름 구성 | 주장과 근거·한계가 맞는지 검토 |

각자 다른 후보를 탐색할 수 있지만, 각자 최고 점수의 조합을 가져오는 경쟁으로 운영하지 않는다. 발견된 제약과 실패도 공동 연구 자산으로 인계한다.

**재현 확인과 독립 검증은 다르다.** 같은 파일과 코드로 같은 결과를 얻는 것은 재현 확인이다. 한 사람이 이미 보고 선택에 사용한 기간은 다른 사람이 실행해도 다시 미열람 자료가 되지 않는다.

각 작업의 인계에는 다음을 남긴다.

1. 알고 싶었던 현상과 이번에 실제 한 일.
2. 입력 자료·공개시각·코드·출력 경로.
3. 확인한 결과와 아직 미실행인 항목.
4. 판정 이유와 다음 행동 하나.
5. 상대방이 검토·재실행한 범위와 발견한 문제.

## 9. 첫 공동 작업에서 채울 문장

> **우리는 쿠싱의 ______가 평소와 달라졌는지 알고 싶고, 그것을 직접 볼 수 없으므로 ______를 관측한다.**

이 문장 최대 세 개를 작성한 뒤 다음 질문을 확인한다.

- 관측이 그 현상과 연결된다고 생각하는 이유는 무엇인가?
- 동일한 관측을 만들 수 있는 다른 원인은 무엇인가?
- 공개 데이터가 실제로 존재하고 최신 자료를 받을 수 있는가?
- 현지 자료인가, 연결된 다른 지역의 맥락 자료인가?
- 비교할 실제 상태 자료가 있는가? 없다면 어디까지 주장할 것인가?
- 단일 관측으로 충분한가? 조합이 꼭 필요하다면 무엇이 추가되는가?

그중 실제 자료를 확보할 수 있는 하나를 첫 사례로 고른다. 아직 특정 데이터나 조합은 확정하지 않았다.

## 10. 첫 결과물과 연구 경계

첫 결과물의 제안은 **설명 가능한 관측 몇 개와 그 변화가 한눈에 보이는 ‘쿠싱 관측판’**이다. 사용자는 관측을 비교하며 해석하고, 우리는 데이터의 의미·시점·한계를 명확히 보여준다. 기존 계획의 화면 구현 범위를 자동 변경하는 문서는 아니며 실제 구축 범위는 별도 확정한다.

실행은 [연구 수집 규칙](../research/INTAKE.md), [검정 규약](testing-protocol.md), [후보 기록 규약](recording-standard.md)을 따른다. 신규 후보와 판정의 정본은 [후보 원장](../research/candidates/ledger.csv) 및 상세 카드다.

WTI를 검정할 때는 Yahoo `CL=F`를 사용하고, 선택·튜닝은 2015–2023 내부에서 수행한다. 기존 2024+ 노출을 지우거나 이름 변경으로 독립 평가를 복구하지 않는다. 최신 관측만 존재하면 운영 시연과 향후 동결 후 평가를 구분하며, 자료가 쌓이기 전에는 예측력을 주장하지 않는다.

이 문서는 대화의 제안과 검토 의견을 정리한 것이다. 새 데이터 수집·조합 실험·회귀분석·모형 검증은 실행하지 않았으며, 특정 관측의 데이터 접근성이나 WTI 관계를 입증하지 않는다.
