# CAI 공동 작업용 AI 프롬프트

[시작 안내](TEAM_START_HERE.md)와 [작업표](CANDIDATE_WORKLIST.md)가 범위 정본입니다. 아래에서 **담당 단계 하나**를 골라 붙여넣습니다. 후보 ID·실제 쓰기 경로·허용한 수집 범위를 채우고 시작합니다. 이 문서나 담당 제안 자체는 외부 수집·학습·발신 승인이 아닙니다.

기존 [메타프롬프트](execution/META_PROMPT_BUILDER.md)의 목표·소유 파일·수용 조건·증거 구조를 사용합니다. 새 과제를 만들 때만 그 메타프롬프트로 아래 실행 카드를 구체화하며, 일반 구현용 CONTINUE_PROMPT로 연구 수집/학습 권한을 대체하지 않습니다.

## 3단계 — 후보 하나 확인·수집

```text
역할: CAI 자료 수집 담당.
프로젝트: LS CRUDE. 먼저 AGENTS.md, research/INTAKE.md, docs/cai/TEAM_START_HERE.md를 읽어.
대상 후보 ID: <작업표의 정확한 ID 하나>
담당/수락 여부: <담당자와 수락 근거>
승인된 취득 범위/다운로드 한도: <실제 승인 내용. 없으면 문서·기존 파일 검토만>
쓰기 범위: <후보별 새 raw 폴더, 날짜 노트, 출처 표의 해당 행>

1. 기존 후보와 확보물을 확인하고 재다운로드를 피한다.
2. 실제 측정량·시설/지역·단위·주기·기간과 원출처를 확인한다.
3. 코드·링크·양식과 실제 관측값을 구분한다. 장기 이력·권리·공개시점이 불명확하면 그대로 적는다.
4. 승인 범위에서만 취득하고 새 원본의 SHA·시각·재취득 방법을 기록한다. 원본을 덮어쓰지 않는다.
5. 노트와 작업표에 확보/차단을 반영한다. 표본 확보를 장기 시계열 완료로 바꾸지 않는다.

결과: 수집 가능/추가 확인/차단 판정, 근거 URL, 실제 원본 경로·hash·기간·행수, 남은 조건, 4단계에 넘길 파일.
금지: 로그인/약관 제한 우회, 승인 없는 대량 수집, 합성값, 모델 학습, OOS 성과 확인, 메시지 발송, 다른 후보 확장.
막히면: 시도한 경로·짧은 원인·필요한 결정 하나를 기록하고 중단. 출처 오류 원문에 인증정보가 있으면 공유하지 않는다.
```

## 4단계 — 원본에서 학습 입력 준비

```text
역할: CAI 전처리 담당.
먼저 AGENTS.md, research/INTAKE.md, docs/cai/TEAM_START_HERE.md의 4단계 계약을 읽어.
후보 ID / 담당: <정확한 값>
읽기 원본: <3단계에서 검토한 실제 파일과 hash>
쓰기 범위: <자기 후보의 새 processed 폴더, 재사용 가능한 전처리 스크립트, 품질 노트>

기존 도구를 찾아 재사용하고, 필요한 최소 변환만 구현해.
원본→시설/지역/단위 필터→중복·결측 검사→date,value CSV의 경로를 재현 가능하게 남겨.
실제 가용일 열이 있으면 관측일과 분리해 보존하고, 없으면 미확인이라 명시해.
월·일 주기 변환이나 재사용은 근거와 범위를 명시한다. 임의 0 채움·역방향 채움·미래 자료 참조는 하지 않는다.
단위, 역할(active 또는 배경/통제), 기간, rows, 결측, 중복, 원본/입력 SHA, 공개/가용시점과 재사용 규칙을 README에 기록해.
모델 표준화나 가중치 학습을 여기서 전체 기간에 수행하지 마.

결과: 입력 CSV(로컬), 품질 요약/검사, 생성 명령·스크립트, 5단계 설정에 필요한 metadata, 입력 준비 또는 차단 판정.
금지: 원본 변경, 다른 단위·통계 기준의 임의 합산, 활동 역할 자동 승인, 모델 실행, OOS 성과 계산, 데이터 무단 업로드.
```

## 5단계 — 고정 설정 실행·결과 제출

```text
역할: CAI 실험 담당.
먼저 docs/cai/TEAM_START_HERE.md와 research/experiments/cai/REPRODUCE_2019.md를 읽어.
담당: <taehwan 또는 seongchan>
승인된 입력 묶음/설정: <실제 config 경로와 입력 hash>
쓰기 범위: <자기 processed 출력 폴더, 자기 submissions 폴더>

새 모델을 만들지 말고 기존 실험 엔진을 사용해.
1. cai_team.py check --config <config>로 검사. EXAMPLE/미확보/표본 부족은 해결 전 실행하지 않는다.
2. 공통 타깃·분할·seed·비교 모델과 성분 역할을 확인한다. 같은 파일 stem 중복과 배경자료 자동 편입을 금지한다.
3. 기존 CLI run --no-cache로 자기 출력 경로에 실행한다. 이미 본 결과로 설정을 수정하거나 반복 튜닝하지 않는다.
4. cai_team.py package로 실제 config와 run을 대조한다. RUN COMPLETE나 compare MATCH만으로 성공 처리하지 않는다.
5. 생성된 README에 결과의 범위·기준선 대비 차이·한계·다음 질문 하나를 쓴다.
6. 정확한 제출 파일만 자신의 브랜치에 담아 PR 검토를 요청한다(사용자가 Git 전달을 승인한 경우).

결과: README/manifest/config/export-summary 네 파일, 검증 결과, run ID, 환경·코드·입력 해시, 해석·실패 사유.
실패: 원래 run을 보존하고 후보/모델 ID와 실패 단계·이유를 보고한다. 결과를 수정해서 검사를 통과시키지 않는다.
금지: raw/CSV/행별 예측/인증정보 Git 업로드, main 직접 커밋, 최종 OOS, PIT 예측, 임의 앙상블, 자동 게시·메시지 발송.
```

```text
역할: CAI 결과 검토자. 작성자와 별도로 검토하되 실제 독립 실행 여부는 증거로 구분한다.

같은 조건이면 재현 일치 여부를, 다른 조건이면 정확히 무엇이 다른지 표로 보여줘.

성공/차단/미검증을 구분하고 통합 가능·보완 필요를 판정해. 원자료·행별 예측을 공개 요약에 넣지 마.
화면 반영은 공개 범위 검토 후 기존 생성기/PR/배포 경로로 한다. 제출 즉시 자동 게시하지 마.

결과: 비교 가능성 표, 실제 수치 대조, 불일치·한계, 반영할 run 목록 또는 보완 요청 한 묶음.
```
