# 다음 구현 AI에게 — CAI 웹사이트 개편

이 문서는 실행 지시 템플릿의 완성 초안입니다. 아직 구현 승인 또는 배포 승인을 뜻하지 않습니다.

## 시작 전
1. 최신 main/작업 브랜치/dirty 상태와 운영 build SHA를 각각 확인한다. 본 계획의 cecf1cf를 최신이라고 가정하지 않는다.
2. 루트 AGENTS.md, README, 현행 docs/cai/PRD.md 및 WEBSITE_PLAN.md, docs/testing-protocol.md, research/INTAKE.md, 지정 태스크를 읽는다. 경로 존재와 최신 버전을 확인한다.
3. 기존 CFAM과 앱의 점수 없음 규칙, 새 CAI 기획이 충돌하면 DEC-01의 승인 범위를 확인한다. 확인이 없으면 연구 규칙을 교체하지 않는다.
4. 태스크 ID, 소유 파일, 입력 run, 완료 기준을 선언하고 단일 작업을 DOING으로 바꾼다. 구현 승인이 없으면 계획/검토 단계에 머문다.

## 실제 구현 순서
history 라우트·옛 URL 보존 → snapshot 타입/검증 → CAI 핵심 컴포넌트 → 연구·히스토리 → 실제 run 연결 → 회귀/접근성/근거 검수 → 배포 승인.
Superpowers 환경에서는 승인된 설계로 작업 계획을 만들고, 기능별 실패 테스트→최소 구현→검증 순서를 따른다. 새 프레임워크 설치나 전체 레포 구조 개편은 하지 않는다.

## 금지
- cfam-engine.ts의 고정/캐시 점수를 학습 결과라고 이름만 바꾸어 쓰지 않는다.
- 모든 원자료를 프런트 bundle로 import하여 비공개 계수를 접기로 숨기지 않는다.
- 누락을 0점으로 표시하거나 캐시 조회시각을 새 관측일로 표시하지 않는다.
- 마지막 미완료 가격봉을 동결된 검정 타깃으로 섞지 않는다.
- OOS 결과로 조합을 다시 고르거나 과거의 노출 상태를 지우지 않는다.
- 문서/목업 작성으로 실증·팀 합의·배포 완료를 주장하지 않는다.
- 원본 자료·기존 장부·CFAM을 삭제하지 않는다. 원장 ID와 링크를 보존한다.
- 이번 작업을 이유로 결제/요금제/권한/시크릿을 변경하지 않는다.

## 검증
실제 package.json과 ci.yml을 다시 읽고 등록된 명령을 실행한다. 확인한 현재 명령은 app에서 npm run typecheck, npm run build 및 ci.yml의 Node 테스트 목록, research에서 원장/관측 export 검사와 pytest다. 없는 npm test 스크립트를 가정하지 않는다.
새 테스트 파일은 실행 경로와 CI에 포함한다. 앱 화면 검수는 현행 AGENTS의 ego 규칙을 따른다. 도구가 없으면 정확한 차단을 기록하고 대체 승인을 받는다.

## 인계 형식
태스크 ID / base·head SHA / 변경 파일 / 입력·출력 run / 실행 명령과 실제 결과 / 화면·근거 링크 / 아직 못한 것 / 승인 필요 항목 / 다음 태스크.
검증 자료는 실제 생성된 것만 연결한다. CI green만으로 운영 전환을 완료 처리하지 않고 footer build SHA와 배포를 대조한다.

## 도구 주의
이번 세션에서는 GitHub 읽기와 Superpowers 기획 절차를 사용했다. ECC·Ponytail·Agency Agents·Vercel 내부 도구 실행은 하지 않았다. 다음 환경에 이 도구들이 있더라도 역할을 무한히 늘리지 말고, 기존 AGENTS의 파일 소유권·위임 규칙을 지킨다.
