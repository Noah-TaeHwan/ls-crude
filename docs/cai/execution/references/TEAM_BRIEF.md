# 성찬님 검토용 — CAI 웹 개편 제안 v0.5

2026-09-11 · 전달용 초안 · 발송/승인 미실행

## 제안 한 줄
기존 LS CRUDE 앱을 없애지 않고, CAI 결과를 보는 홈 + 현재 연구 근거 + 과거 히스토리로 정리하자는 제안입니다.

## 이번 확인에서 달라진 점
최신 main cecf1cf에는 별도 CFAM HTML/엔진이 추가되었습니다. 고정 PINCH와 WIKI/EIA의 잔여 비중을 사용하는 실험입니다. 반면 앱 홈·쿠싱 상세는 기존 연구 데스크/점수 없음 구조입니다. 대화에서 만든 CAI v4는 가상 UI 목업입니다. 이 세 가지를 같은 구현/연구 상태로 보지 않겠습니다.

## 화면은 이렇게
- 대시보드: CAI 계기판·추이, 다음 기간 WTI 방향, WTI 가격만 우선 표시.
- CAI란?: 정의·구성 영역·가중치 정책·현재 검증 한계를 접어서 제공. 가상/미학습 표시는 숫자 곁에 유지.
- 연구·검증: 현재 CAI 후보와 실제 run·기준 모델 대비 결과.
- 히스토리: 기존 CFAM·관측·보류·기각·방향 전환. 원본과 URL 보존.

## 합의가 필요한 부분
1. CFAM은 별도 탐색 사례로 보존하고, 새 CAI의 성분·목적·산식을 따로 동결할지.
2. 동일 비중 기준선과 학습 비중 실험을 비교하되, 최종 OOS에서 재선택하지 않는지.
3. 실제 데이터/학습/독립 검증/게시 승인을 별도 상태로 보여줄지.
4. 태환 제품·데이터·웹·기록 / 성찬 학습·검정·반증 역할과 실제 가용 시간을 어떻게 나눌지.
5. 공개할 데이터 근거·계수의 범위와 발표 전 최소 release 범위.

## 바로 다음 작업
OPS-01에서 실제 운영 build와 차단 원인을 확인하고, DATA-01에서 편입 가능한 자료를 판정합니다. 승인 후 README·현행 기획의 연결을 정리하고 history 이동과 CAI 빈 상태부터 작은 PR로 구현합니다. 실제 run이 없으면 점수/확률을 만들지 않습니다.

현재 코드의 CI 실패·Vercel 차단은 확인했지만 관리 화면/운영 렌더와 원인은 미확인입니다. 사이트 장애 또는 팀 권한 문제라고 단정하지 않습니다.
