## 선택 규칙
BOOT-01 먼저. OPS-01과 DATA-01은 다른 결과를 기다리지 않고 읽기 점검 가능하나 기본 한 실행자·한 단위다. 승인된 문서 연결 후 S1a와 S2a는 서로 독립이다. 작은 계약을 먼저 확정하는 실행자는 S2a를 먼저 할 수 있다. 동일 파일 동시 쓰기 금지.

S1 부모 완료는 S1a/S1b 모두 검수 통과했을 때, S2는 S2a/S2b/S2c, S3는 S3a/S3b 모두 통과했을 때만 제안한다. 기존 UI-05 전체 DONE은 이들 모두의 수용 조건·검수를 확인해야 한다.

QA-02 기본은 UI-06 이후다. 데이터가 없는 빈 상태 release를 명시 승인받았을 때만 UI-06 대신 S3b 검수 완료와 NO_DATA 표시를 조건으로 QA를 진행한다. 이 예외로 실제 데이터·학습 완료를 주장하지 않는다.

새 카드의 선행조건은 기술적 순서다. 기존 원장의 DEC/IDX/ML/게시 승인 의존성을 무시하지 않는다. 현재 권한·배포 장애가 있으면 그 카드만 BLOCKED이며, 승인된 다른 로컬 작업의 가능 여부를 별도로 판단한다.

## 이번 패키지의 제외 범위
DATA-02/RES-01/IDX-01/ML-01/ML-02/EVAL-01의 수집·학습을 자동 실행하는 프롬프트가 아니다. 그 작업은 데이터 판정·실험 승인 뒤 META_PROMPT_BUILDER로 별도 카드로 만든다. 기존 통계·수집 규약은 유지한다.
