# REL-01 — 승인 후 프리뷰·운영 전환 및 복구 확인

기존 원장 연결: **REL-01**. catalog 등록은 착수/완료 승인이 아니다.

## 목표와 경계
승인 후 프리뷰·운영 전환 및 복구 확인를 한 변경 단위로 수행한다. 다른 카드의 작업을 함께 끝내려고 범위를 늘리지 않는다.

## 선행조건
- 카드 선행: QA-02, OPS-01
- 승인/조건: 원격 배포/alias 변경 명시 승인 + QA 검수 PASS + OPS 복구 근거

## 먼저 읽을 파일
- `.github/workflows/ci.yml`
- `app/app/components/desk-chrome.tsx`
- `실제 배포 대상 SHA와 마지막 정상 배포 기록`
- 기획서 절: 12

## 쓰기 허용 파일
- 앱/연구/배포 파일 변경 없음. 실제 결과 기록만 허용.
- 실행 결과는 `docs/cai/execution/runs/<unit_id>/<run_id>/RESULT.md`에 새로 남길 수 있다. 기존 원장의 상태 변경은 원장 권한·스키마를 확인한 경우만.
- 신규 경로가 이미 있으면 내용을 읽어 확장/재사용한다. 목록 밖 파일 변경 필요 시 범위 변경을 요청한다.

## 입력·출력 / 실행 결정
코드 쓰기 목록은 비어 있다. 승인된 배포 액션은 파일 수정과 별도다. 설정 변경이나 새 배포 코드는 이 카드에 포함하지 않는다.

## 실행 순서
1. 실제 승인자·대상 SHA·환경·허용한 원격 동작·마지막 정상 배포를 확인한다. 없으면 읽기 보고로 종료한다.
2. 승인된 범위의 공식 Vercel/GitHub 도구만 사용하여 프리뷰 상태와 CI를 대조한다.
3. 프리뷰에서 실제 build·핵심 경로·데이터 상태를 검수한다.
4. 운영 변경까지 승인된 경우에만 대상 변경을 수행하고 운영 footer/alias/SHA를 확인한다.
5. 차이가 있으면 실패로 기록하고 승인된 복구 절차만 사용한다. 설정/멤버/요금제를 자동 변경하지 않는다.
6. 오프라인 발표 자료·롤백 가능 여부와 실제 미실행을 기록한다.

## 수용 조건
| ID | Given / When | Then / 확인 방법 |
|---|---|---|
| REL-01-AC1 | 배포 승인 없음 | 원격 변경 없음 |
| REL-01-AC2 | CI/preview PASS만 확보 | production 완료를 주장하지 않음 |
| REL-01-AC3 | 운영 검증 | 대상 SHA·alias·footer 실제 대조 |

## 필수 회귀·인계
현행 package.json/CI에서 해당 영역의 명령을 직접 확인한다. 코드 변경은 관련 테스트와 typecheck/build, UI 변경은 승인된 브라우저 검수를 추가한다. 기존 실패·새 실패·도구 차단을 구분한다. 문서/읽기 작업은 관련 경로·숫자·인용·미실행 상태를 대사한다.
수용 조건별 PASS/FAIL/NOT_RUN, 실제 명령/cwd/exit, 변경 diff, 남은 승인/의존성, 다음 카드 하나를 RESULT에 적는다. 실행자는 REVIEW에서 멈춘다.

## 중단 조건
승인 부재, 필수 입력/소스 미접근, 허용 범위 밖 변경, 연구 규칙·공개 정책 충돌은 BLOCKED. 확인된 구현 결함은 REVISION. 모든 결과를 얻기 위해 로그/스크린샷/값을 만들어 채우지 않는다.
