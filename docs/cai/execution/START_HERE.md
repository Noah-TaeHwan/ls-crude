# CAI 실행 안내 — v0.6

**기준:** 웹 개편 기획서 v0.5 + 이번 사용자의 실행 프롬프트 작성 요청. 새 제품 방향/연구 규칙/팀 역할/배포를 대신 승인하는 문서가 아니다.

## 1. 지금 제공된 것

이 패키지는 `기획 → 작업 하나 → 검증 → 인계`를 연결한다. 장문의 “전문가처럼 완벽히 해라” 대신 수정 파일·인터페이스·테스트 입력·실패 시 행동을 정했다. 현재 제품 요구는 [기획서 원문](SPEC_REFERENCE_v05.md)에 있고 원문은 수정하지 않았다. [핵심 맥락](PROJECT_BRIEF.md)은 찾기 위한 요약이지 새로운 요구사항의 정본이 아니다.

원격 GitHub에는 설치하지 않았다. 문서 생성기와 패키지를 검증했지만 실제 모델 실행·앱 구현·수집·학습·배포는 하지 않았다.

## 2. 3번의 대화로 시작

**첫 대화:** ZIP과 루트 `BOOTSTRAP_PROMPT.md`의 블록을 전달한다. AI는 문서를 안전하게 설치하고 BOOT-01을 수행한다. 도구로 확인할 수 없는 레포 경로는 마지막에 질문한다.

**둘째 대화:** BOOT 보고에서 추천한 작업 하나를 승인한다. [CONTINUE_PROMPT](CONTINUE_PROMPT.md)의 블록을 사용한다. 기존 task의 승인·선행조건이 없으면 관련 구현은 멈추되 DATA-01/OPS-01의 읽기 점검처럼 허용된 다음 행동을 제안한다.

**셋째 대화:** 새 대화/별도 검수자에게 [REVIEWER_PROMPT](REVIEWER_PROMPT.md), 작업 패킷, 실제 diff·실행 증거를 전달한다. 같은 모델의 자기 검사는 SELF_CHECK이며 독립 리뷰를 대체하지 않는다. 단위가 통과하면 원장 담당자가 기존 tasks.json에 근거를 반영한다.

## 3. 실행 패킷을 만드는 법

레포 루트에서 Python 3가 사용 가능한지 확인한 뒤:

```bash
python3 docs/cai/execution/make_packet.py --list
python3 docs/cai/execution/make_packet.py --check
python3 docs/cai/execution/make_packet.py --task BOOT-01
python3 docs/cai/execution/make_packet.py --task UI-05.S2a
```

마지막 명령은 작업의 공통 규칙, 카드, 필요한 계약, 관련 기획서 절, 결과 형식을 **표준출력**으로 만든다. 필요하면 셸 리다이렉트로 새로운 파일에 저장한다. 예: `> /tmp/cai-UI-05-S2a.md`. 이미 중요한 파일이 있는 경로로 출력하지 않는다. Python이 없으면 카드에 적힌 문서를 직접 읽으면 되고, 새 의존성을 설치할 필요는 없다.

패킷 생성은 실행 승인/태스크 준비 완료 판정이 아니다. 패킷은 실제 소스코드를 포함하지 않는다. AI는 해당 작업의 소스와 실제 명령을 추가로 읽어야 한다. 출력에 포함된 기획서 절을 통째로 다시 요약할 필요는 없다.

## 4. 한 번에 읽는 범위

첫 세션만 현행 문서의 위치·승인·충돌을 정리한다. 이후에는 **적용되는 AGENTS + 공통 규칙 + 선택 카드 + 명시된 계약/기획 절 + 해당 코드 + 직전 인계**를 읽는다. 전체 repo/과거 실험/OOS 결과를 습관적으로 펼치지 않는다. 필요한 근거가 빠졌으면 그 파일만 추가로 읽는다. 문서 개수나 글자 수를 맞추기 위해 중요한 검증 조건을 생략하지 않는다.

카드의 경로는 기획서 스냅샷 기준이므로 존재 여부를 확인한다. 경로가 옮겨졌으면 실제 대응 경로를 입증해 인계에 기록한다. 범위·인터페이스가 달라지면 카드 수정 검토를 먼저 받고, 빈 파일을 만들며 진행하지 않는다.

## 5. 원장·리뷰·실행 권한

- 기존 `docs/cai/tasks.json` 또는 팀이 승인한 Issues/Projects **하나만** 정본이다. 현재 정본이 없으면 누락 사실을 보고하고 새 완료 원장을 발명하지 않는다.
- `catalog.json`은 작업 방법 목록이다. live 상태, 담당 수락, 팀 합의가 들어 있지 않다. 파일 존재는 완료 증거가 아니다.
- 실행 결과는 `templates/RESULT_TEMPLATE.md` 형식을 사용한다. 레포 쓰기가 허용되면 `docs/cai/execution/runs/<unit_id>/<run_id>/RESULT.md`에 새 기록으로 남긴다. run_id는 실제 UTC 시각 등 충돌 없는 식별자다.
- 한 작업의 종료는 기본 REVIEW 요청이다. SELF_CHECK만으로 DONE을 쓰지 않는다. 기존 CI 실패가 있어도 원인·범위·실행한 검사를 구분하며 전체 green을 주장하지 않는다.
- 문서 설치, 로컬 코드 수정, 커밋, push/PR, 원격 배포, 연구 실행은 각각 권한이다. 이번 패키지가 push/PR/배포 권한을 자동으로 주지 않는다. 승인된 로컬 단위 안에서는 매 줄마다 재허락을 묻지 않는다.

## 6. 모델과 역할

일반 구현은 한 실행자에게 카드 하나만 준다. 복잡한 모형 선택·계약 변경·배포 원인 진단이 막히면 문제를 더 작은 명세로 고치거나, 그 결정만 검토자에게 보낸다. 큰 모델을 항상 오케스트레이터로 켤 필요는 없다. 사람도 같은 검수 절차를 사용할 수 있다.

ECC/Ponytail/Superpowers/Agency Agents 등은 **현재 환경에서 실제 발견된 스킬/도구만** 사용한다. 이름만 보고 역할·명령·성공을 만들어내지 않는다. 서로 충돌하면 repo의 현행 규칙과 실제 실행 환경 지시를 먼저 대조한다. 플러그인 필수화를 이유로 가능한 읽기·정적 검사를 멈추지 않는다.
