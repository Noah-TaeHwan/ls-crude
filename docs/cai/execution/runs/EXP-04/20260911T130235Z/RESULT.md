## 1. 시점 정렬 문제 — 확인·수정 (외부 리뷰 지적 재현)

- **재현**: 구 코드 `series.shift(availability_lag_days)`는 **행 이동**이라 월별 자료에서 1일 지연이
  "다음 행(다음 달)" 이동이 된다. 단위 테스트로 월별(01-31=10, 02-28=20) 재현.
- **수정**: `align_availability()` — 관측일 → (가용일 열 우선, 없으면 +달력일) → 의사결정일.
  - 가용일 **이전에는 노출 안 함**, 역방향 채움 없음, `validity_days=0`이면 가용일 정확 일치만,
    `validity_days>0`이면 그 일수만큼만 forward 사용(무제한 ffill 금지), 초과 시 NaN(채움 아님).
  - 상태 분리: `CONFIRMED_RECEIVED_DATE`(녹취된 접수일) / `ASSUMED_LAG_DAYS`(가정) /
    `RECORDED_OBSERVATION_DATE`(회고 관측일 정렬). PIT 모드의 availability_basis 게이트는 유지.
- **테스트**: 월별 달력일, 주말 관측, 유효기간 경계, 접수일 우선·조기 노출 차단, 비채움,
  준비 단계 상태/재사용 카운트 포함 **19/19 통과**(신규 7건). E2E: 주말·월말·결측·DST 미채움 확인.
