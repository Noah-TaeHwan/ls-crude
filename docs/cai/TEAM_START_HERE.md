- 당시 작업 원칙은 새 자료가 막혀도 기존 2개 공통 실험을 맞추고, 서로 다른 기간·중복 측정의 자료를 개수 때문에 합치지 않는 것이었습니다. 프로젝트 종료 후 새 실험을 자동 실행하지 않습니다.
- 이번 학습 묶음은 회고 연구입니다. 전향 관측 후보·보류/기각·배경/통제는 활동 성분에 자동 포함하지 않습니다. 최종 OOS와 현재 예측 게시를 열지 않습니다.

## 3단계 완료 조건 — 원자료 또는 명확한 차단

기존 [INTAKE](../../research/INTAKE.md)를 따릅니다. 원출처, 실제 측정량, 지역/시설, 기간·주기·단위, 취득 방법, 이용 조건, 관측일·공개시점, 파일 SHA를 기록합니다. 링크·코드·양식만 있으면 실측 수집 완료가 아닙니다.

원자료는 `research/gathering/raw/<후보ID>/<수집시각>/`의 새 폴더에 보존합니다. 원문 덮어쓰기, 무단 대량 수집, 접근 제한 우회는 하지 않습니다. 이용 조건과 다운로드 한도가 불명확하면 원인과 필요한 결정을 적고 멈춥니다. 연구 노트·출처 표·작은 manifest를 Git에 남깁니다.

작업표의 복합 표시 ID(`CAAI / 091-O` 등)를 폴더명에 그대로 붙이지 않습니다. 기존 정본 카드 ID 또는 안전한 영문 slug를 사용하고 README에 원래 후보 ID와 연결합니다. 실험의 `candidate_id`·입력 파일명도 공백·슬래시 없는 식별자를 사용합니다.

## 4단계 완료 조건 — 프로그램이 읽는 입력과 의미 설명

- 입력 위치: `research/data/processed/<후보ID>/<run>/`. 다른 사람의 입력을 덮어쓰지 않습니다.
- CSV 기본 열: `date,value`. 실제 이용 가능 시각이 있으면 별도 열을 두고 `available_at_column`에 지정합니다. 미확인 공개일을 관측일로 만들어 채우지 않습니다.
- README: 무엇을 재는지, 단위, 시설·지역, 원주기, 공통 기간, 행 수, 중복·결측, 필터·집계, 관측→가용 정렬, 재사용 기간과 이유, source/input 해시를 기록합니다.
- 결측은 공백으로 남깁니다. 월별 값을 매일 재사용해도 독립 관측 수는 늘지 않습니다. 다른 단위·통계 기준을 임의 합산하지 않습니다.
- 원자료를 CSV로 정리하는 작업과 모델의 표준화는 다릅니다. 모델 표준화 통계는 기존 프로그램이 학습 구간에서만 구합니다.
- 입력 준비와 측정 타당성·권리·PIT 적격성은 별개입니다. 확인되지 않은 조건은 그대로 남깁니다.

## 5단계 — 같은 프로그램으로 실행하기

환경은 [DELIVERY](../../research/DELIVERY.md)를 따릅니다. 아래는 **저장소 루트 기준**입니다. macOS/Linux의 `research/.venv-share/bin/python`을 사용하며, Windows PowerShell에서는 `research\.venv-share\Scripts\python.exe`로 바꿉니다. 가상환경을 새로 만들거나 의존성을 다시 설치할 필요가 없는 경우 기존 동일 환경을 사용합니다.

### 먼저 기존 기준 실험 맞추기

입력 파일의 확보·해시는 [REPRODUCE_2019](../../research/experiments/cai/REPRODUCE_2019.md)에서 확인합니다. 입력 CSV는 Git에 없습니다. 확보하지 못하면 해당 입력 이름·해시에서 멈추고 알립니다. 담당자별 출력 폴더를 사용합니다.

```bash
research/.venv-share/bin/python research/scripts/cai_team.py check --config research/experiments/cai/pilot_retro_traffic_dmr_2019.config.json
research/.venv-share/bin/python -m ls_crude.experiment.cli run --config research/experiments/cai/pilot_retro_traffic_dmr_2019.config.json --base-dir research/data/processed/cai-seongchan --no-cache
```

태환은 `--base-dir research/data/processed/cai-taehwan`을 사용합니다. `check`는 입력과 유효 표본을 검사하며 학습하지 않습니다. 기존 2019 설정의 metadata 누락 예외는 정확히 그 고정 설정에만 적용되며 경고를 표시합니다. `RUN COMPLETE` 또는 종료코드 0만으로 모든 모델 성공을 판정하지 않습니다.

### 새 후보를 넣는 실험

1. [TEAM_INPUT_TEMPLATE.json](../../research/experiments/cai/TEAM_INPUT_TEMPLATE.json)을 **별도 설정**으로 복사합니다. EXAMPLE/placeholder는 실행할 수 없습니다.
2. 검토된 활동 성분만 `components`에 명시합니다. 각 입력의 `unit`·`availability_basis`, 성분의 `role: active`, 고유 파일명, 실제 SHA를 채웁니다. `active`는 이번 실험의 성분 역할이며 공식 채택 승인이 아닙니다.
3. 가용일 열·지연·유효기간을 근거로 명시합니다. 주기가 다른 자료에 임의 지연이나 무제한 채움을 적용하지 않습니다. 설정의 분할·seed·타깃을 결과를 본 뒤 바꾸지 않습니다.
4. 같은 `check`로 입력/표본을 확인하고 위 `run --no-cache`의 config만 새 경로로 바꿉니다. 자료가 부족하면 실패/차단으로 기록합니다.

타깃은 다음 5거래일 WTI 상승 여부, 보합은 하락과 함께 분류합니다. 기존 6개 비교 모델(상승률 기준선, 시장정보, CAI 동일/학습가중, 시장정보+CAI 동일/학습가중)을 재사용합니다. 최종 OOS·새 알고리즘 탐색·PIT 예측은 이 공동 패키지의 범위가 아닙니다.

공동 v1 비교 조건은 **IS 2015–2023, 학습 종료 2020-12-31, 평가 후보 2021–2023, seed 7, 시장정보 RSI14·5일 수익률, 6개 모델 각 1개**로 고정합니다. 실제 평가 날짜는 공통으로 유효한 자료에 따라 줄어들 수 있으며 두 결과에서 다시 대조합니다. 다른 타깃·분할·seed·모델 구성이 필요하면 이 묶음과 구분한 새 실험 규약부터 정합니다. `check` 통과는 형식·입력·계산 가능성 확인이며 통계적으로 충분한 표본이나 예측력의 승인이 아닙니다.

## 결과를 GitHub에 제출하기

실행 출력의 실제 run 경로를 사용합니다. 아래 `<run_id>`는 실제 값으로 바꾸고, 제출 폴더는 존재하지 않는 새 경로여야 합니다.

```bash
research/.venv-share/bin/python research/scripts/cai_team.py package --config research/experiments/cai/pilot_retro_traffic_dmr_2019.config.json --run-dir research/data/processed/cai-seongchan/<run_id> --owner seongchan --out research/experiments/cai/submissions/seongchan-<run_id>
```

새 조합이면 `--config`도 실제 실행한 설정으로 바꿉니다. 태환은 `--owner taehwan`과 태환 경로를 사용합니다. 제출 검사 통과도 통계적 개선·권리·독립 재현·공개 승인을 뜻하지 않습니다.

제출 파일은 **README.md·manifest.json·config.json·export/summary.json** 네 개입니다. 검사기는 기대 모델·상태·설정/입력/코드·표본·지표와 내부 예측을 대조합니다. CSV·원자료·내부 로그는 제출 묶음에 넣지 않습니다. README의 해석/한계/다음 질문을 작성하고 PR에 아래 내용을 요약합니다.

| PR에 남길 내용 | 예 |
| --- | --- |
| 담당·후보·작업 범위 | 성찬 / CAAI / 수집·전처리 또는 고정 실험 |
| 무엇을 확보했나 | 지역·측정량·기간·주기·행 수·실제 경로 |
| 검증 | check/package 결과, 입력 hash, run ID, code fingerprint |
| 결과·해석 | 기준선과의 차이, 한계, 다음 질문 하나 |
| 차단 시 | 어디서 멈췄는지·왜인지·필요한 접근/자료. 실패 원문에 인증정보가 있으면 복사하지 않음 |

자기 feature branch에서 정확한 파일만 commit/push하고 PR을 만듭니다. main 직접 commit/push, 다른 사람의 변경 포함, 원자료·큰 입력 파일·행별 예측 업로드는 하지 않습니다. GitHub Issue는 실제 착수한 후보의 작업 추적에만 사용하고, 담당자 지정·멘션은 수락/발신 확인 뒤 진행합니다.

## 두 결과를 모으는 방법과 월요일 작업

- 같은 입력·타깃·분할·모델·seed라면 먼저 재현 일치를 확인합니다. 불일치는 환경/설정/입력 차이부터 조사합니다.
- 다른 실험은 표본·조건을 명시해 나란히 표시합니다. 다른 데이터의 지표나 예측값을 임의 평균하지 않습니다.
- 태환 측이 제출 묶음을 검토한 후 기존 공개 요약 생성 경로로 화면에 연결합니다. **학습 실행이나 PR 제출만으로 운영에 자동 게시되지 않습니다.**
- 월요일에는 검토된 결과의 해석·화면 연결·발표 흐름을 정리합니다. 새 자료가 없으면 기존 실험과 수집 차단 결과도 정직하게 설명합니다.
