# LS CRUDE — 아이디어에서 데이터, 관측판, 인디케이터까지

작성일: 2026-09-08 · 대화 정리: Codex · 상태: 실행 흐름 제안

이 문서는 [쿠싱 관측판·협업 워크플로우](cushing-observation-workflow-2026-09-08.md)의 작업 순서를 간단하게 구체화한다. 특정 데이터의 확보·검증이나 웹사이트 구현이 완료됐다는 뜻은 아니다.

## 1. 기본 방향

**아이디어를 내고 → 실제 데이터를 구할 수 있는지 확인하고 → 관측 가능한 것을 하나씩 보여주고 → 함께 볼 이유가 있는 것들을 조합한다.**

처음부터 좋은 상관관계나 복잡한 모형을 찾으려 하지 않는다. 데이터 확보와 관측 가능성을 먼저 확인하며, 불가능한 아이디어에는 이유를 남기고 다음으로 넘어간다.

```text
가설·아이디어
    ↓
데이터를 구할 수 있는가?
    ├─ 없음 → 보류 이유·재개 조건 기록 → 다음 아이디어
    └─ 있음 → 허용된 실제 샘플 확보
                    ↓
          의도한 관측을 할 수 있는가?
                    ├─ 없음 → 관측 범위 수정 또는 보류·종료
                    └─ 있음 → 개별 시각화
                                  ↓
                           웹사이트 관측판
                                  ↓
                      함께 볼 이유가 있는가?
                          ├─ 없음 → 개별 관측 유지
                          └─ 있음 → 소수 데이터 조합
                                          ↓
                                 설명 가능한 인디케이터
```

‘데이터가 없다’는 것은 현재 접근·구성 방법을 진행할 수 없다는 뜻이다. 가설 자체가 거짓이라고 입증한 것은 아니다.

## 2. 모텔 불빛 아이디어로 따라가기

> **아이디어:** 쿠싱 모텔의 불빛이 많아지면 사람이 많아졌고, 지역 활동이 바빠졌다는 단서일 수 있지 않을까?

아래는 작업 예시이며 실제 데이터 확보나 관측 결과가 아니다.

| 단계 | 확인하거나 수행할 일 |
| --- | --- |
| 아이디어 | 어떤 모텔·구역의 어떤 변화를 알고 싶은지 적는다 |
| 데이터 탐색 | 해당 장소의 밝기를 날짜별로 확보할 수 있는지 확인한다 |
| 샘플 확보 | 실제 자료 일부와 출처·관측시각·수집시각을 보존한다 |
| 관측 가능성 | 해상도가 충분한지, 같은 장소·비교 가능한 시간대인지 확인한다 |
| 첫 시각화 | 우선 ‘모텔 주변 야간 밝기 변화’를 표시한다 |
| 해석 검토 | 사람 증가 외에 조명 교체·날씨 등 다른 설명을 살펴본다 |
| 조합 검토 | 다른 활동 관측과 함께 보는 것이 해석에 도움이 되는지 확인한다 |

**밝기 데이터를 확보한 것과 사람 수를 확보한 것은 다르다.** 밝기만 측정했다면 지표도 밝기로 명명한다. 투숙객 수나 원유 관련 업무량으로 바꾸어 부르지 않는다.

모텔을 구분하지 못하는 도시 전체 밝기 자료라면, 원래 질문에는 부적합할 수 있다. 관측 범위를 도시 전체로 바꿔 별도 가설로 기록하거나 해당 접근을 보류한다.

## 3. ‘데이터 있음’의 기준

데이터 소개 페이지를 찾은 것만으로 수집 완료라고 하지 않는다. 다음을 구분한다.

| 상태 | 의미 | 다음 행동 |
| --- | --- | --- |
| 출처 발견 | 제공자가 관련 자료를 안내함 | 실제 접근·이용 조건 확인 |
| 샘플 확보 | 허용된 실제 자료 일부를 받음 | 단위·지역·시각·해상도·결측 확인 |
| 관측 가능 | 샘플로 의도한 관측을 할 수 있음 | 필요한 기간·갱신 방식 확인 후 시각화 |
| 보류 | 접근·역사 범위·최신성 등 조건 미충족 | 이유와 재개 조건 기록 |
| 현 접근 종료 | 확보한 자료가 원하는 현상을 측정하지 못함 | 종료 범위를 기록하고 다음 아이디어로 이동 |

샘플 확보는 전체 시계열 수집 완료나 지속 운영 가능성을 보장하지 않는다. 샘플·부분 수집·필요 기간 수집을 구분한다.

수집할 때는 원본, 출처, 관측·공개·수집시각, 단위와 지역, 이용 조건을 남긴다. 지금 다운로드한 과거 자료를 당시에도 사용 가능했던 값이라고 가정하지 않는다. 자세한 절차는 [INTAKE](../research/INTAKE.md)를 따른다.

## 4. 데이터가 쌓이면 먼저 개별 시각화

쓸 만한 데이터가 10개 남았다면 먼저 각각 보여준다. **10개는 채워야 할 목표가 아니라 탐색 결과의 예시**다. 모두 모일 때까지 기다리지 않고 확보된 관측부터 순서대로 정리할 수 있다.

각 카드에는 다음을 표시한다.

- **무엇:** 실제로 측정한 대상·단위·지역.
- **언제:** 관측시각과 자료의 최신성. 필요한 경우 공개·수집시각도 표시.
- **변화:** 원 단위 추이와 평소 대비 변화, 비교 기준.
- **한계:** 해석 가능한 범위와 아직 확인하지 못한 것.

비교 가능한 같은 계절·요일·시간대인지 확인한다. 결측·접근 실패를 활동 0으로 표시하거나, 오래된 값을 현재 정상 상태처럼 보여주지 않는다. 역사 자료가 부족하면 ‘평소보다 높다’는 판단도 보류한다.

**개별 관측을 정확하게 보여주는 관측판 자체가 첫 완성품이다.** 아직 가격 예측력이나 종합 점수가 없어도 된다. 실제 웹사이트 구현 범위는 별도로 정하며, 이 문서는 구현 착수를 뜻하지 않는다.

## 5. 조합은 선택 단계

관측이 여러 개 있다고 모두 섞을 필요는 없다. 다음 질문에 답할 수 있는 것부터 소수로 조합한다.

1. 같은 활동이나 상태를 나타내는 관측인가?
2. 거의 같은 정보를 중복해서 세고 있지는 않은가?
3. 하나만 볼 때보다 함께 보면 무엇을 더 알 수 있는가?
4. 단위·빈도·공개시점이 달라도 정직하게 비교·결합할 수 있는가?

예를 들어 서로 다른 관측이 같은 활동을 나타낸다는 근거가 있다면, 각 관측의 평소 대비 변화를 정리해 요약 지표를 제안할 수 있다. 아직 구체적인 구성 자료나 산식은 확정하지 않았다.

조합 지표에는 다음을 공개한다.

- 포함한 자료와 제외한 자료의 기준.
- 정규화·산식·가중치와 그 이유.
- 결측·오래된 관측이 있을 때의 처리.
- 각 자료가 최종 값에 기여한 정도.
- 지표가 나타내는 활동과 나타내지 못하는 것.

자료가 추가·누락돼 구성 자체가 달라졌다면 이를 실제 활동 변화와 혼동하지 않는다. 합친 값의 해석이 불분명하면 개별 관측을 유지한다.

## 6. 회귀분석과 가격 검정은 언제 하는가?

**관측판이나 활동 인덱스를 만드는 데 회귀분석은 필수가 아니다.** 실제 재고·운송량처럼 추정할 목표와 비교 자료가 정해졌을 때 모형을 검토한다.

| 질문 | 적절한 다음 작업 |
| --- | --- |
| 관측값이 평소와 달라졌는가? | 비교 기준을 정하고 개별 시각화 |
| 여러 관측을 함께 보면 활동을 더 잘 이해할 수 있는가? | 구성 근거를 설명한 소수 조합 |
| 실제 상태를 얼마나 잘 추정하는가? | 정답 자료와 단순 기준을 정한 모형 평가 |
| 이후 WTI와 어떤 관계가 있는가? | 별도의 타깃·시점·기간을 고정한 검정 |

수많은 조합 중 과거 상관관계가 가장 높은 것을 찾는 작업을 기본 흐름으로 삼지 않는다. 조합을 시험한다면 실패·변환·시차·가중치 변경도 기록하고, 선택과 평가를 구분한다. 실제 검정은 [검정 규약](testing-protocol.md)을 따른다.

## 7. 두 사람의 운영 방식

역할은 [협업 문서](cushing-observation-workflow-2026-09-08.md)의 제안을 따른다. 실제 담당 수락을 확인했다는 뜻은 아니다.

- **Noah:** 아이디어·출처 탐색, 실제 샘플 수집, 관측 시계열과 첫 시각화.
- **성찬:** 원하는 현상을 측정하는지 검토, 품질·시점·대체 설명 확인, 필요한 분석 설계.
- **공동:** 보류·진행 판단, 상대 작업 재현, 함께 볼 이유가 있는 자료 선정.

첫 반복 단위는 **아이디어 → 실제 샘플 → 관측 가능 여부**다. 이 단계는 빠르게 진행하되, 원문 확보와 측정 적합성 확인을 생략하지 않는다. 깊게 조사하는 후보는 기존 [프로젝트 계획](project-plan.md)의 최대 3개 제안을 참고해 제한한다.

실제 아이디어는 [후보 원장](../research/candidates/ledger.csv)과 상세 카드에 기록한다. ‘데이터 없음’·‘샘플만 있음’·‘관측 가능’이라는 설명은 원장의 수집 상태·검정 상태·판정을 대신하는 별도 상태 체계가 아니다. [기록 규약](recording-standard.md)에 맞춰 해당 필드에 요약한다.

## 8. 두 단계의 완성품

| 완성품 | 제공하는 가치 | 완료를 위해 확인할 것 |
| --- | --- | --- |
| **첫 번째: 쿠싱 관측판** | 확보한 관측과 변화를 정확하게 보여준다 | 실제 자료·측정 정의·시각·비교 기준·한계 |
| **두 번째: 조합 인디케이터** | 함께 볼 이유가 있는 관측을 이해 가능한 값으로 요약한다 | 조합 근거·산식·기여도·결측 처리·해석 범위 |

조합이 유용하지 않다면 첫 완성품에서 멈춰도 된다. 두 결과물 모두 그 자체로 WTI 예측력이나 투자 성과를 입증하지 않는다.

이번 문서는 대화에서 제안한 흐름을 정리한 것으로, 신규 데이터 수집·지표 구성·검정·웹사이트 변경은 수행하지 않았다.
