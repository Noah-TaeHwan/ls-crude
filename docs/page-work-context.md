# 메인·리서치 화면 정리 맥락

기준: 2026-09-09. 이 문서는 화면 개편을 이어받는 사람과 AI의 진입점이다. 과거 논의를 다시 해석하기보다 현재 사용자 결정과 실제 코드를 먼저 확인한다. Git·배포·자료 기준일은 변하므로 아래 과거 SHA를 현재 상태로 가정하지 않는다.

## 1. 프로젝트가 하려는 일

LS CRUDE는 WTI와 연결될 수 있는 흥미로운 활동 대리변수를 찾는 미니 프로젝트다. 출발점은 펜타곤 피자 인덱스 같은 **활동 → 관측 가능한 데이터 → 시계열 → 시장 연결 가설**이다.

성공은 반드시 예측력이 좋은 지수를 찾는 것이 아니다. 무엇을 시도했고, 어떤 자료를 실제로 구했으며, 왜 보류·기각했는지를 근거로 설명할 수 있어야 한다. 관측 자료 확보와 WTI 관계 검정은 별개다. 그림이 생겼다고 검증된 지수가 된 것은 아니다.

## 2. 왜 화면을 나눴나

처음에는 자료가 늘 때마다 홈에 별도 관측 카드를 추가했다. LA항 빈 컨테이너도 수박·제주·도일과 다른 위치에 놓였고, 메인과 리서치 양쪽에서 같은 그래프를 반복했다. 상단 메뉴에는 페이지와 페이지 안의 절이 섞여 있었다.

사용자가 다음 방향을 정했다.

1. LA항을 기존 수박·제주·도일의 버튼 묶음에 넣는다.
2. 시정·탱커 입항도 같은 자료 탐색 UI로 묶는다.
3. 메인은 소개·WTI 일봉·자료 탐색의 세 영역만 남긴다.
4. 상단 메뉴는 메인/리서치 두 페이지로 정리한다.
5. 리서치는 메인과의 중복을 없애고 목적부터 다시 설계한다.

## 3. 두 페이지의 역할

| 페이지 | 방문자가 얻을 답 | 주요 내용 |
| --- | --- | --- |
| 메인 `/` | 어떤 자료를 확보했고 실제 관측값은 어떠한가? | 짧은 소개, WTI 단일 일봉, 여섯 자료 선택 |
| 리서치 `/research` | 무엇을 측정하려 했고, 근거가 충분한가? 다음에 무엇을 확인하나? | 가설·작업 상태·판정·다음 행동, 상세 근거, 과거 검정 기록 |

메인은 관측, 리서치는 검토와 인계가 중심이다. 리서치에 그래프를 다시 복제하지 않는다. 자료를 보고 싶으면 메인의 해당 선택값으로 연결한다.

## 4. 메인 구성

### 소개

`EAST CAMP AI QUANT 4기 / 오태환 × 손성찬`. 프로젝트 목적과 현재 연구 상태를 간단히 안내한다.

### WTI 일봉

`01 / WTI DAILY`. Yahoo Finance `CL=F` 단일 일봉 그래프를 사용한다. 5년·3년·1년·6개월·3개월·1개월·1주일 모두 일봉 기준이며 기본은1년이다. 다른 가격 그래프나 독립 실시간 가격판을 임의로 추가하지 않는다.

### 통합 자료 탐색

`RESEARCH IN PRACTICE / 자료 탐색`. 모든 자료는 한 버튼 묶음에서 고른다.

| 자료 | URL 선택값 | 성격 |
| --- | --- | --- |
| 수박 · 냉장트럭 | `/?sample=watermelon#research-sample` | 고정 과거 연구 표본 |
| 제주 · LNG와 유류 | `/?sample=jeju#research-sample` | 고정 과거 연구 표본 |
| 미국 · 냉난방도일 | `/?sample=degree-days#research-sample` | 고정 과거 연구 표본 |
| LA항 · 빈 컨테이너 | `/?sample=empties#research-sample` | 고정 과거 연구 표본 |
| 갤버스턴 · 시정 | `/?sample=visibility#research-sample` | 갱신 관측 |
| 싱가포르 · 탱커 입항 | `/?sample=tankers#research-sample` | 갱신하는 월간 관측 |

여섯 개는 현재 표시 대상 수이며 영구 상한이 아니다. 새 자료를 표시할 때도 이 묶음을 재사용하고 확보 범위·권리·최신성부터 확인한다.

같은 선택 UI를 쓴다고 최신성까지 같은 것은 아니다. 고정 표본에는 자동 갱신 아님을 표시한다. 시정·탱커는 기존 캐시·조회시각·지연 표시·갱신 버튼을 유지한다. 월간 입항은 실시간 항만 상황이 아니다.

기존 FIELD NOTES 독립 영역과 홈의 RESEARCH INTAKE / THE SIGNAL HUNT / WHAT REMAINS OPEN은 제거했다. 이 내용을 다시 홈의 네 번째·다섯 번째 영역으로 되살리지 않는다.

## 5. 리서치 구성

핵심 질문: **어떤 가설을 더 확인할까?**

- ALT 가설 장부가 주 화면이다. 검색·작업 상태·후속 판정은 함께 적용한다.
- 작업 상태는 원본 확보, 차단·실패, 검정 미실행 등 실제 기록에서 읽는다.
- 카드에서 가설·관측 대상·확보 상태·판정 이유·다음 행동을 먼저 보여준다.
- 확보 범위·공개 시점·측정 한계·검토 결과·원문·변경 이력은 필요할 때 펼친다.
- 과거 factors 검정 장부는 별도 접힌 참고 영역이다. 기존 검색과 후보 딥링크를 유지한다.
- 판정 방법과 출처 문서도 접어서 제공한다. 팀 소개나 큰 소개 배너를 반복하지 않는다.
- 리서치에서 외부 관측 API 조회와5분 polling은 제거했다.

ALT와 기존 factors는 서로 겹치는 별도 기록이다. 건수를 합산하거나 전체 연구 완료율로 만들지 않는다. 원본 확보와 검정 미실행 역시 겹칠 수 있다. KEEP은 효과 인증이 아니라 후속 연구 유지다.

정렬은 등록 ID 역순이며 최근 수정 순서가 아니다. 담당·재검토일은 기록상 정보이고 사람의 수락이 확인되지 않았다면 배정 제안으로 표시한다.

## 6. 연결과 원문

- `SAMPLE_LINKS`가 후보 카드에서 메인 자료로 가는 연결을 관리한다.
- 옛 `/research?sample=…` 주소는 메인의 같은 자료로308 연결한다.
- `/research?candidate=018#ledger` 같은 과거 후보 링크는 유지한다.
- `/observations/empties`는 메인의 LA항 사례로 연결한다.
- 시정·탱커 상세는 세부 근거를 보는 보조 경로이며 상단 주 메뉴를 늘리지 않는다.
- GitHub 후보 카드·원장·노트가 정본이다. 웹은 이를 읽어 보여준다. 편집·저장·AI 작업 실행 화면으로 확대하지 않았다.

## 7. 이번 감독 검토에서 배운 것

trout 작업은 자료 확보 자체는 진전이 있었지만 앱 CI가 실패한 상태에서 병합돼 있었다. 원본 수치와 UI의 분모가 다른 경우, 실제 HTTPError 대신 반환값만 검사한 자가검사, 원본/출력 보존 문제도 발견했다.

원 작업자에게 교정을 맡기고 감독자가 따로 재현했다. 단순한 완료 보고를 승인하지 않고 원본→계산→화면→문서→CI를 대조했다. 자료 오류를 맞추려고 원본 숫자를 고치거나 검사 기준을 낮추지 않았다.

[trout 감독 기록](reviews/2026-09-09-trout-supervision.md) · [메인 통합 PR #92](https://github.com/Noah-TaeHwan/ls-crude/pull/92) · [리서치 개편 PR #95](https://github.com/Noah-TaeHwan/ls-crude/pull/95).

## 8. WTI 빈 화면 후속 확인

리서치 개편의 마지막 운영 검수에서 WTI 빈 화면을 발견했다. Yahoo HTTP 요청은 성공했지만 응답의 마지막 두 행이 같은 뉴욕 날짜여서 기존 파서가 전체를 거부했다.

2026-09-09T02:20:10Z에 확보한5년 응답(repo empirical only):

| 원천 시각 UTC | 뉴욕 달력일 | Open / High / Low / Close |
| --- | --- | --- |
| 2026-09-08 04:00:00 | 2026-09-08 | 92.26 / 94.73 / 90.87 / 93.03 |
| 2026-09-09 02:10:05 | 2026-09-08 | 94.31 / 94.78 / 94.15 / 94.38 |

두 행은 시가·저가도 달라 같은 일봉 갱신이라고 단정할 수 없다. [CME WTI 거래시간 안내](https://www.cmegroup.com/education/courses/event-contracts-underlying-markets/wti-overview)는 야간 거래가 있음을 설명하지만, 이 Yahoo 추가 행의 정확한 거래일을 증명하지는 않는다. [yfinance의 처리 코드](https://raw.githubusercontent.com/ranaroussi/yfinance/main/yfinance/utils.py)도 참고했으나 단순 마지막 행 우선을 그대로 적용하지 않았다.

복구 정책은 좁다. 모든 행의 종목·배열·시각·OHLC를 먼저 검사한다. 마지막 인접 중복이고, 마지막 시각이 `regularMarketTime`과 같고, 직전 유효 행이 같은 뉴욕 날짜의 자정 라벨인 경우에만 모호한 추가 행을 제외한다. 다른 중복·역순·동일 timestamp·잘못된 가격은 계속 거부한다.

기존 일봉을 합산·수정하거나 추가 행을 다음 날짜로 추정 이동하지 않는다. `missingCount`와 `excludedTail`을 구분하고 표시 가격·원천 시각은 보존한 마지막 일봉 기준이다. UI에는 **확인 가능한 일봉**, 제외 시각, 최신 실시간 가격 미보장을 표시한다.

위 응답에서1261원행 =1257유효일봉 +3 OHLC결측 +1 모호한 추가 행이다. 유효1257행은 추가 행을 제거하기 전 원본 prefix의 OHLC·거래량과 전수 일치한다. 작은 실제 재현 표본은 [테스트 fixture](../app/tests/fixtures/yahoo-duplicate-tail.json), 구현은 [일봉 파서](../app/app/lib/wti-daily.ts)와 [차트](../app/app/components/wti-daily-chart.tsx)에 있다. 전체 수신 캡처는 로컬 `/tmp/ls-crude-yahoo-duplicate.json`으로만 보존했으며 영구 원본 저장소가 아니다.

**제약:** 빈 차트 복구와 최신 추가 시세의 일봉 귀속 해결은 다르다. 정확한 거래일 근거가 확보되기 전에는 그 행을 정상 일봉으로 합치지 않는다. 중복이 없는 정상 응답은 기존 방식으로 자동 표시한다.

## 9. 다음 AI가 이어받을 때

1. 현재 AGENTS.md·관련 스킬·Git 상태를 확인한다. 이 문서의 숫자와 과거 배포 상태를 현재 사실로 가정하지 않는다.
2. 메인/리서치 역할과6자료의 최신성 구분을 유지한다.
3. 기존 정본·컴포넌트를 재사용하고 새 점수·모델·데이터를 임의로 만들지 않는다.
4. 변경된 로직의 정상·실패 경로를 검사한다. SSR fixture 통과는 실제 Yahoo 데이터 정상성 증거가 아니다.
5. Ego로 모바일·검색·필터·딥링크·빈/오래된 상태를 확인한다.
6. 로컬 테스트, CI, 병합, main 동기화, 배포 SHA, 실제 화면을 각각 확인한다.

## 10. 이번 후속 검증

실제 최소3행 fixture와 전체1261행 캡처를 각각 대사했다. metadata 불일치/중간중복/3중복/역순/동일시각/미래시각/결측직전행/잘못된 OHLC·거래량/겨울 시간대/음수·0가격 반증을 검사했다. 독립 Reality Checker 정적검토 후 직전 자정행 결측 검사도 추가했다. 타입 검사·빌드·Node27개 검사와 실제 로컬390/1440px·7기간 전환을 확인했다. [수치·브라우저 증거](design-evidence/wti-tail-recovery/). 배포·Git 최종 상태는 해당 변경 PR의 최신 영수증을 확인한다.
