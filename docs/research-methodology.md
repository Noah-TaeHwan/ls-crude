# 대안 데이터 연구 방법론

이번 연구의 질문은 **“관측 가능한 현실의 활동이 WTI 선물과 어떤 관계를 보이는가?”**입니다. Pentagon Pizza Index는 활동 → 민감한 맥락 → 시장이라는 사고의 참고입니다. 피자 데이터나 crypto×news 조합은 필수가 아닙니다.

이 문서는 새 후보를 다루는 절차입니다. [기록 표준](recording-standard.md), [검정 규약](testing-protocol.md)을 함께 사용합니다. 기존 `research/factors/`·노트·실험의 결과를 재검증했다고 뜻하지 않습니다. 이번 작업은 운영 체계 준비이며 새 지수 발견이나 검정 완료를 주장하지 않습니다.

## 1. 질문과 검색 범위를 먼저 적기

1. [후보 템플릿](../research/candidates/_TEMPLATE.md)을 `research/candidates/ALT-YYYYMMDD-NN.md`로 복사합니다. 같은 날짜의 미사용 번호를 고릅니다.
2. [장부](../research/candidates/ledger.csv)에 한 행을 연결합니다. 기존 팩터라면 원래 번호·노트 링크를 남겨 중복 탐색을 드러냅니다.
3. 한 줄 가설: **어떤 활동이, 어떤 지역·맥락에서, 어떤 경로로 WTI의 무엇과 관련될 수 있는가?**
4. 활동과 민감한 맥락을 나눕니다. “배송 활동”과 “정책기관 비상근무”처럼 적되, 연결은 검증 전 가설임을 표시합니다.
5. 검색한 사이트·데이터베이스, 정확한 검색어, 검색일, 언어, 요구 역사 기간, 포함·제외 기준을 기록합니다. 발견 → 중복 제거 → 접근 확인 수를 실제 기록에 근거해 셉니다.

뉴스·시장의 반응을 재포장한 신호인지, 실제 행동을 관측한 것인지 구분합니다. 활동 자체의 대리 정도, 반대 설명(계절·서비스 성장·보도량 등), 가설을 버릴 조건도 적습니다. 검색 실패는 “이 범위에서 확인하지 못함”이지 세계에 데이터가 없다는 증명이 아닙니다.

## 2. 출처와 접근 경로 확인

| 확인 | 남길 증거와 통과 조건 |
| --- | --- |
| 출처 | 원 제공자 URL, API/다운로드 문서, 실제 확인일; 소개 글이면 원 제공자로 추적 |
| 의미 | 원 관측·기관 집계·공급자 추정·재인용을 구분; 재인용 여러 개를 독립 증거로 세지 않음 |
| 접근 | `public / needs_key / scrape / manual / unavailable` 중 하나와 실제 접근 방법 |
| 범위 | 제공 시작·종료일, 단위·빈도·지역, 결측, 비용·할당량·갱신 지연 |
| 권리 | 저장·분석·재배포 허용 범위, 라이선스/ToS URL·확인일·불명확한 항목 |
| 윤리 | 공개/허용된 집계인지, 개인 식별·재식별 위험과 최소 수집 범위 |

`scrape`는 접근 분류일 뿐 수집 허가가 아닙니다. 허용 근거가 불명확하면 수집을 보류하고 `collection_status=BLOCKED`, `decision=PARK`와 해제 조건을 적습니다. 금지된 접근이 필수면 `KILL`; 키·유료 접근이 필요하면 소유자·비용·대체 경로를 기록합니다. 인증 우회나 타인의 자격증명은 사용하지 않습니다.

가격은 **Yahoo `CL=F` WTI 선물**을 사용합니다. Investing.com 뉴스는 사람이 제공한 CSV가 정본이며 스크래핑하지 않습니다. 다른 출처를 쓰는 경우 용도·출처를 명시하며 WTI 타깃을 현물·다른 자산으로 바꾸지 않습니다.

새 출처는 [출처 레지스트리](../research/gathering/sources/REGISTRY.md)에 등록하고 기존 출처는 연결합니다. 링크가 있다는 사실만으로 접근·역사 데이터 확보·사용 허가를 확인했다고 쓰지 않습니다.

## 3. 수집: 원본은 그대로, 시도도 기록

원본은 `research/gathering/raw/<id>/<retrieval-timestamp>/`에 저장하고 덮어쓰지 않습니다. `retrieval-timestamp`는 UTC `YYYYMMDDTHHMMSSZ` 형식입니다. 실패 재시도도 별도 시도로 남깁니다. 키가 포함된 URL·헤더·쿠키는 기록에서 제거합니다.

수집 영수증에 출처, 키를 제거한 요청 파라미터, 수집시각, 응답/실패 상태, 실제 데이터 기간·행수·단위, 파일 경로·SHA-256, 제공자 버전/개정 정보를 기록합니다. API가 성공을 반환해도 빈 본문이면 수집 완료로 처리하지 않습니다.

- `NOT_STARTED`: 아직 수집하지 않음. 초기 판정 `PARK`는 단순 대기이며 차단을 뜻하지 않습니다.
- `COLLECTING`: 일부를 받는 중. 완료 범위와 남은 범위를 구분합니다.
- `COLLECTED`: 필요한 원본과 수집 영수증이 존재함. 곧바로 검정 가능·성공을 뜻하지 않습니다.
- `BLOCKED`: 접근·권리·역사 구간 등 선행조건 미충족. `FAILED`: 실제 수집 시도가 실패함.

원본·대용량 데이터·시크릿은 Git에 넣지 않습니다. 원본 경로만으로 팀원 재현이 불가능하면 허용된 전달 경로 또는 동일 원본을 얻는 절차를 적고, 미확보 상태를 남깁니다.

## 4. 정제: 당시 알 수 있었던 값만

정제 규칙을 실행 전에 후보 기록에 적고 `research/notebooks/<id>/`의 실행 가능한 노트북/스크립트로 남깁니다. 파생 데이터는 `research/data/processed/<id>/`에 저장합니다. 원본 수정은 금지하며, 오류 수정은 새 원본 버전·변경 이유로 추적합니다.

| 항목 | 규칙 |
| --- | --- |
| 시간 | `observed_at`, 제공자 공개시각 `published_at`, 최초 사용 가능 `available_at`, 수집시각 `retrieved_at`을 구분 |
| 이용 가능성 | 발표·처리 지연과 시간대를 반영; `available_at` 이후 첫 허용 WTI 의사결정 시점에만 결합 |
| 개정 | 관측 당시 빈티지를 사용; 최신 수정본밖에 없으면 `NOT_PROVEN as-of-safe`와 제한 기록 |
| 품질 | 중복·결측·단위 변경·지역/서비스 커버리지 변경을 검출하고 처리 전후 행수 기록 |
| 결측 | 미수집·접근 실패를 활동 0으로 채우지 않음; 허용된 이월도 공개 이후·유효기간 안에서만 |
| 빈도 | 저빈도 원천의 실제 발표 단위를 유지; 일별 반복값을 독립 표본 수로 세지 않음 |

발표시각이 없으면 임의의 당일 사용을 허용하지 않습니다. 제공자 문서에 근거한 보수적 지연 계약을 적고, 근거까지 없으면 선행성 검정을 보류합니다. 현재 받은 과거 자료가 당시에도 공개돼 있었다고 추정하지 않습니다.

## 5. 지수 명세를 고정

`research/indexes/<id>/`에 명세와 실행 영수증을 둡니다. 후보를 만들었다는 이유로 지수 CSV를 생성하지 않습니다. 다음 항목이 채워져야 실제 구성 단계로 갑니다.

- 관측 대상·지역·포함/제외 모집단, 원시 단위, 지수 단위, 빈도, 기준 시간대.
- 산식과 집계 방법(합계·평균·비율 등), 분모, 가중치, 최소 커버리지·관측 수.
- 계절성/추세 처리, 표준화 기준 기간·창 길이, 결측·0분산·이상치 처리.
- 입력 파일·해시·코드 경로·버전, 예정 출력 경로, 지수 명세 버전. 출력 해시와 실행 영수증은 실제 구성에 성공한 뒤 기록합니다.
- 값이 커지는 의미와 한계: 활동량, 관심도, 공급자 추정치를 서로 바꾸어 부르지 않음.

표준화·가중치·특징 선택은 허용된 학습 기간에서만 결정합니다. 롤링 기준은 미래를 쓰지 않고 `t` 이전 정보만 사용합니다. 기준값과 가중치를 WTI 결과에 맞춰 바꾸면 새로운 변형으로 기록합니다. 작은 원시 단위의 시계열도 충분하며, 0–100 점수나 복합지수는 필수가 아닙니다.

## 6. WTI와 비교하고 전부 기록

[검정 규약](testing-protocol.md)에 따라 주 타깃·시차·기간·통제·placebo·판정 조건을 먼저 고정합니다. **선택/튜닝은 2015–2023**, 2024+는 적격 후보를 동결한 뒤 한 번만 평가합니다. 이미 본 2024+ 결과와 최근에만 존재하는 자료는 규약의 별도 경로를 따릅니다.

자료가 있으면 커버리지 → 지수 시계열 → WTI 상관/시차 → 필요한 사건·placebo 확인 순으로 진행합니다. 미실행 검정은 `NOT_RUN`, 실제 실행은 `RUN`과 실행 ID·결과 경로를 남깁니다. 실패·무관계·부호 반전·불확실성을 함께 기록하고 가장 좋아 보이는 시차만 보고하지 않습니다.

활동 proxy와 WTI의 관계를 보는 데 매매 전략·ML·Sharpe가 필수는 아닙니다. 매매 성과를 주장하는 별도 실험에만 거래 시점·비용·기준 전략을 추가합니다. 상관이나 사건 전후 변화만으로 인과·수익성을 주장하지 않습니다.

## 7. KEEP / KILL / PARK 결정

| 결정 | 의미 | 필수 다음 기록 |
| --- | --- | --- |
| `KEEP` | 현재 증거가 다음 연구 투입을 정당화함; 알파 발견·배포 승인 아님 | 통과한 조건, 남은 반증, 다음 검정·담당·기한 |
| `KILL` | 현 가설/구성은 중단: 메커니즘 부재, 금지된 접근 필수, 품질 실패, 사전 조건 미충족 등 | 구체적 이유·증거 링크, 중단한 가설의 범위; 기록을 삭제하지 않음 |
| `PARK` | 아직 판단 못 함: 초기 대기·자료 부족·접근 차단·독립 검증 대기 등 | 이유, 재개 조건, 다음 행동·담당·재검토 날짜 |

통계적 비유의만으로 “관계가 절대 없다”고 쓰지 않습니다. 검정력이 부족하면 `PARK`; 정해 둔 진행 조건을 충족하지 못해 중단한다면 그 범위에서 `KILL`입니다. `KEEP`라도 검증 안 된 지수에는 생산 가중치를 주지 않습니다.

후보 원문은 같은 ID 경로에 보존합니다. 기각·차단은 [원장의 상태별 조회](recording-standard.md#상태판정과-조회)로 보여주며, 별도 rejected/blocked 폴더나 결과 정본을 만들지 않습니다. 판정 변경은 이전 값·변경일·이유를 이력에 남깁니다.

## 8. 동료 검토와 발표 인계

작성자 외 팀원이 원본/접근 영수증 → 정제 → 명세 → 검정 결과 → 판정의 연결을 확인합니다. 검토자·날짜·발견 문제·수정 증거·남은 제한을 후보 기록에 적습니다. 문제 수정 후 영향을 받은 표·그림만 다시 만들고 재검토합니다. 검토했다는 말만으로 재현 완료를 선언하지 않습니다.

발표할 수 있는 최소 묶음은 **질문·탐색 경계·후보 장부·출처/접근 상태·판정 이유·다음 행동**입니다. 데이터가 있으면 재현 가능한 지수와 정직한 비교를 추가하고, 없으면 실패 영수증과 해제 조건을 시연합니다. 09-15까지 유효 지수를 찾지 못해도 이 과정을 설명할 수 있으면 연구 이야기를 완성할 수 있습니다. 구체적 일정과 분담은 [PM 계획](project-plan.md)을 따릅니다.
