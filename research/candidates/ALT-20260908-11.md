# ALT-20260908-11 — Telecom Signaling Mobility Workflow Scope

## 1. Requested pipeline audit

| step | CFAM assessment |
| --- | --- |
| collect mobile signaling / CDR | **BLOCKED.** Carrier-held data; no public CFAM collection path and no attempt made to access it. |
| assign users to base stations | **Not permitted for this project.** This requires raw network metadata and carries individual-location privacy risk. |
| reallocate to 100m/site grid | **Not permitted.** A small hub and fine grid create re-identification risk; no such data is collected or inferred. |
| weekday/night/shift adjustment | Technically possible only inside a licensed provider's already aggregated product. No input exists here. |
| validate with traffic/Census/on-site observations | Methodologically valid only after lawful aggregate zones and a written data-governance contract exist. |

## 2. Data collection result

**No raw signaling data, CDR, device identifier, tower assignment, coordinates, home/work inference, or individual trajectory was collected.** This is a deliberate privacy and access boundary, not a temporary download error.

## 3. Minimum lawful future specification

A future vendor/operator path would have to supply only pre-aggregated, time-bucketed zone counts with minimum-cell suppression, no persistent identifiers, no device-level export, stated retention/revision policy, and explicit authorization for research reuse. A 100m grid is rejected by default; zone size and thresholds must be determined by the provider's privacy program.

## 4. Decision

**BLOCKED / E1.** This is not a free public-data route and cannot be used to rescue CFAM. If a licensed, privacy-reviewed aggregate product is independently procured, it starts as a new data-access review and is first validated against fixed traffic counts—not EIA or WTI.
